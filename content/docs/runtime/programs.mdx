A Program is software as the System knows it. Its identity remains stable while
its installed files, active development source, and live Processes may change.
This makes the Program the place where long-lived resources and policy belong,
rather than attaching them to one temporary execution.

## Identity and declaration

Every Program has a kebab-case `identity` used by the System and a resolved
human name. It may also declare a version, description, icon, agent document,
Server Endpoint, and Client Endpoint. The resolved `server` and `client`
members describe what a default Process should start and whether each Endpoint
should begin as a Service.

```ts
const program = await system.program.find("notes")

if (program) {
  console.log(program.identity, program.name, program.version)
  console.log(program.server?.start, program.client?.start)
}
```

`system.program.list()` returns the Programs visible to the caller.
`system.program.find(identity)` returns one visible Program or `null`.
`system.program.create(source)` creates an uninstalled runtime Program from a
definition or an absolute `program.json` path. `forceCreate()` claims the same
identity for a new runtime Program while preserving installed files and
storage.

`assetId` identifies the current runtime incarnation used by Client asset URLs.
It may change when the Program is replaced; the public Program identity does
not.

## Processes belong to the Program

A Program is the only place from which one of its Processes is created. It can
list, find, create, replace, run, and exit those Processes without turning the
System-wide Process collection into a second ownership path.

```ts
const process = await program.createProcess({
  name: "editor",
  client: true,
  options: { document: "welcome.txt" },
})

const same = await program.findProcess("editor")
console.log(same === process)
```

`processes()` returns all live Processes owned by the Program.
`firstProcess()` and `lastProcess()` select them by creation time, and
`findProcess()` accepts either an identity or a Program-local name.
`exitProcesses()` ends them all and returns their identities.

See [Processes](/runtime/processes) for Launch, replacement, parentage, and
attached runs.

## Saved launches

The Program owns two persisted Launch values with different purposes.
`program.launch` is used when a person opens the Program from its icon.
`program.startup` is used when the System starts and immediately after the
Program is installed.

```ts
await program.launch.set({
  name: "main",
  options: { document: "home.txt" },
})

await program.startup.enable({ name: "background", server: true })
```

`launch.get()` and `startup.get()` return the stored Launch or `null`.
`startup.disable()` removes only the startup instruction; it does not stop a
currently running Process. Both capabilities work on installed and attached
Programs. Only installed Programs are reconstructed during System boot.

A declaration may provide `launch` or `startup` as `true` or as a Launch.
`true` stores an empty Launch. Omission makes no decision and leaves a stored
value unchanged. Declared values are applied when the Program is created and
when it is installed.

## Program-owned resources

Resources survive independently from any one Process:

- `data` stores durable files.
- `cache` stores disposable files.
- `store` provides persistent key-value state.
- `database` provides writable SQLite data.
- `logs` provides read-only access to captured Endpoint output.
- `permissions` owns the Program's authoritative permission state.

All Processes of the Program see the same resources. Access through either
Endpoint still follows the caller's visible Program scope and the applicable
permission boundary.

## Installation and runtime form

An installed Program runs from files owned by the System and can be restored
after a restart. An attached Program runs directly from a project and remains
tied to the connection that introduced it. Both are the same Program domain;
their file ownership and lifetime differ.

`install()` and `uninstall()` are async generators because their commands can
produce ordered `stdout` and `stderr` chunks:

```ts
for await (const chunk of program.install({
  launch: { name: "main", client: true },
  purge: true,
})) {
  console.log(chunk.stream, chunk.text)
}
```

Installation keeps the existing Processes alive while the installation command
runs. Immediately before the Program switches to its installed definition and
paths, those Processes end. An explicit `launch` runs from the new Program
first, followed by configured startup. A failure in either launch does not
undo a completed installation.

For installation, `purge: true` removes previous installed storage before the
new declaration is applied. Uninstallation normally removes only the installed
form. With `purge: true`, it also ends Processes, removes storage, and forgets
the runtime Program. Calling ordinary uninstallation when the installed form is
already absent completes without producing output or another lifecycle event.
An explicit purge still removes the remaining runtime Program and storage.
`forget()` always ends live Processes and removes the runtime Program without
uninstalling its files.

## Lifecycle

A Program emits `processCreate` and `processExit` for its own Processes. It
emits `uninstall` with `{ purge }` when its installed form is removed, and
`forget` when the runtime Program leaves the registry. The System-level Program
collection publishes the corresponding `create`, `install`, `uninstall`, and
`forget` events for all visible Programs.
