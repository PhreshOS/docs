A Program is the stable software identity known by the System. It is the domain
root for configuration, resources, installation, startup, and live Processes.

## Identity and declaration

Every Program has a kebab-case `identity` and a runtime `assetId`. The public
identity remains stable; the asset identity distinguishes the current runtime
entity used to serve its Client files.

A Program may declare a name, version, description, icon, agent document,
Server Endpoint, Client Endpoint, and immutable Client permissions. It must
declare a Server, a Client, or both.

## Runtime forms

<Tabs items={["Installed", "Attached"]}>
  <Tab value="Installed">
    Production files live under System storage. The Program can be reconstructed
    after a System restart and may keep one startup launch.
  </Tab>
  <Tab value="Attached">
    Development or production files run directly from a local project. The
    Program remains tethered to the connection that started it.
  </Tab>
</Tabs>

Only one current runtime Program occupies an identity. Replacing a runtime
Program does not silently uninstall files or erase storage.

## Owned capabilities

Every Program owns:

- `process`, for creating and observing its Processes;
- `startup`, for one persistent Process launch;
- `data`, `cache`, `store`, `database`, and `logs`;
- `permissions`, for stored user grants; and
- its icon and optional agent document.

## Lifecycle

| Operation | Contract |
| --- | --- |
| `system.program.create()` | Create an uninstalled runtime Program |
| `system.forceCreateProgram()` | Replace the current runtime entity while preserving installed files and storage |
| `install()` | Install the Program while yielding command output |
| `uninstall()` | Remove its installed form while yielding command output |
| `forget()` | End its Processes and remove only its runtime entity |
| `fork(identity)` | Create another Program under a new identity |
