A Service is a stable communication address for an Endpoint that chose to be
reachable. It lets another part of the System communicate with that Endpoint
without owning its Process or controlling its lifecycle.

## Addressing a Service

A Service key identifies a Process and one of its Endpoint kinds. A
Program-local Process name also needs the Program identity that gives the name
its namespace:

```ts
const browser = system.service({
  program: "web-browser",
  process: "main",
  endpoint: "server",
})
```

This address follows replacement Processes created under the same name. If the
key uses a globally unique Process identity, the Program coordinate is not
needed and the address refers only to that exact Process:

```ts
const exact = system.service({
  process: process.identity,
  endpoint: "server",
})
```

`system.service(key)` creates or reuses the canonical handle synchronously. It
does not search for a provider or start one.

## Availability without ownership

A Service follows the addressed Endpoint's `start` and `stop` lifecycle and
reports its current availability through `exists()` and `waitReady()`. It can
publish and observe application events. A Server Service can also ask
questions; a Client Service does not gain that Server-only capability.

```ts
browser.lifecycle.subscribe("stop", () => console.log("Browser unavailable"))

await browser.waitReady()
const result = await browser.ask("page.open", { url: "https://example.com" })
```

The handle intentionally has no `start()`, `stop()`, `enable()`, or `disable()`
operation. Those belong to the Endpoint and Process owners. The Service only
addresses whatever valid incarnation currently occupies its coordinates.

## Becoming a Service

An Endpoint declaration sets the default Service role. A Launch may override
that role for one incarnation:

```ts
const process = await program.createProcess({
  name: "main",
  server: { service: true },
  client: false,
})
```

`endpoint.isService()` and `context.isService()` report the resolved role.
A Client may address Services belonging to its own Program. Foreign Services
become visible through the `services`, `programs`, or applicable `all`
permission; see [Permissions](/system/permissions).
