A Service is a stable communication address for an Endpoint that declared a
service role. It provides communication without controlling the Endpoint.

## Address

```ts
const service = system.service({
  program: "web-browser",
  process: "main",
  endpoint: "server",
})
```

When `process` is a Program-local name, `program` supplies its namespace. The
Service then follows replacement Processes created under that name. A globally
unique Process identity needs no Program coordinate and addresses only that
Process:

```ts
const exact = system.service({
  process: process.identity,
  endpoint: "server",
})
```

## Service role

A Program declaration may provide the default role:

```ts
server: {
  location: "dist/server",
  service: true,
}
```

Omission means `false`. Boolean Endpoint selection uses that declaration
default. An object launch can override it for one incarnation:

```ts
await program.process.create({
  name: "main",
  server: { service: true },
  client: false,
})
```

Client launches accept `service` alongside Window options. The same
`ServerLaunch` and `ClientLaunch` contracts apply to Process creation and later
`server.start()` or `client.start()` calls. Each fresh Endpoint incarnation
therefore resolves its own role. `context.isService()` and
`endpoint.isService()` read that role. Only `system.service()` creates a Service
handle.

## Availability

`system.service(key)` creates or reuses the exact local handle synchronously. It
does not discover providers, list Services, start a Process, or imply readiness.

| Operation | Contract |
| --- | --- |
| `exists()` | Read whether the addressed Endpoint incarnation exists |
| `waitReady()` | Wait up to ten seconds by default for a usable Client or ready Server |
| `subscribe()` | Observe application events from the service address |
| `lifecycle` | Observe the Endpoint's `start` and `stop` transitions |
| `ask()` | Ask a Server Service and await its answer |

A Service has no lifecycle controls.

```ts
service.subscribe("changed", message => console.log(message))
service.lifecycle.subscribe("stop", () => console.log("unavailable"))
await service.ask("value") // Server Service only
```

## Service classes

The public hierarchy is:

- `Service`
- `ServerService`
- `ClientService`

`ServerService` adds `ask()`. `ClientService` adds no operation beyond the
shared Service contract. All three constructors are exported by the relevant
SDKs and preserve reference identity within one SDK context.
