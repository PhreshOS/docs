A Service is one live Endpoint binding under an exact key:

```ts
const browser = system.service({
  program: "flambo",
  endpoint: "server",
  name: "browser",
})
```

An Endpoint explicitly enables or disables its Service. Ending the Endpoint
removes the live binding.

`system.service(key)` creates or reuses the exact local handle synchronously. It
does not discover providers, list Services, start a Process, or imply that the
Service is ready. Application events are subscribed to directly on the handle;
a Server Service can also be published to or asked directly. `service.lifecycle`
separately exposes `enable` and `disable`, while `enabled()` and `waitReady()`
remain root operations.

```ts
service.subscribe("changed", message => console.log(message))
service.lifecycle.subscribe("disable", () => console.log("unavailable"))
await service.ask("value") // Server Service only
```

## Service classes

The public hierarchy is:

- `Service`
- `ServerService`
- `ClientService`

These constructors are exported by the relevant SDKs and preserve reference
identity in one context. They do not use a `Handler` suffix.

<Callout>
  Service discovery and Program agent documentation are independent. A document
  does not create a Service, and a Service does not require a document.
</Callout>
