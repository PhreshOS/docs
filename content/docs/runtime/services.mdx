A Service is a stable communication address for an Endpoint incarnation that
declared a Service role. It provides communication without controlling the
Endpoint.

## Address

```ts
const service = system.service({
  program: "web-browser",
  process: "main",
  endpoint: "server",
})
```

When `process` is a Program-local name, `program` supplies its namespace and
the Service follows replacement Processes under that name. A globally unique
Process identity needs no Program coordinate and addresses only that Process:

```ts
const exact = system.service({
  process: process.identity,
  endpoint: "server",
})
```

`system.service(key)` synchronously creates or reuses the canonical handle. It
does not discover providers, list Services, start a Process, or imply readiness.

A Client can address Services belonging to its own Program without a permission.
The `services` permission grants Services belonging to selected Programs, while
the `programs` permission grants both the selected Programs and their Services.
An empty Program list means every Program. See [Security](/system/security) for
the complete authority contract.

## Shared contract

| Member | Contract |
| --- | --- |
| `lifecycle` | Addressed Endpoint's `start` and `stop` events |
| `exists()` | Whether a matching Service incarnation exists |
| `waitReady(timeout?)` | Wait for a usable Client or ready Server |
| `publish()` | Send an application event to the address |
| `subscribe()` | Persistently observe an event or every event |
| `waitFor()` | Wait for the next matching application event |
| `events()` | Iterate matching or correlated application events |

`ServerService` additionally provides `ask()` and `timeout()`.
`ClientService` adds no operation to the shared Service contract. A Service has
no `start()`, `stop()`, `enable()`, or `disable()` operation.
Lifecycle `start` and `stop` messages are `undefined`, matching Endpoint
lifecycle.

```ts
service.subscribe("changed", message => console.log(message))
service.lifecycle.subscribe("stop", () => console.log("unavailable"))
await service.ask("value") // available because this is a Server Service
```

## Service role

A Program declaration supplies the default role for each Endpoint kind:

```ts
server: {
  location: "dist/server",
  entryFile: "main.js",
  service: true,
}
```

Omission means `false`. An object launch can override the default for one
incarnation:

```ts
await program.process.create({
  name: "main",
  server: { service: true },
  client: false,
})
```

The same `ServerLaunch` and `ClientLaunch` contracts apply to Process creation
and later `server.start()` or `client.start()` calls. `context.isService()` and
`endpoint.isService()` read the resolved role.

## Availability and identity

A Client Service is ready when its incarnation exists. A Server Service must
also have announced readiness. Temporary absence remains waitable; permanent
unavailability rejects. Calls use ten seconds by default.

`Service`, `ServerService`, and `ClientService` are public classes. Repeated
lookup of one address within the same SDK context returns the same handle, so
reference equality and `instanceof` are meaningful.
