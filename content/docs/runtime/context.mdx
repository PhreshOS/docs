title: Context
description: The capabilities belonging to the Endpoint currently executing.

---

A Context is the runtime's first-person view. It belongs to one running
Endpoint execution context and answers: Which Process am I part of? What launched me? Who
created that Process? Which messages are addressed to me?

This is different from retaining an Endpoint handle. The handle is a
permanent handle. The Context exists only while the current execution context is
executing.

Client code imports `context` from `@phreshos/client`. Server code imports
`context` from `@phreshos/server`. Node and the CLI are not an executing
Endpoint, so they have `system` without a Context.

## Execution identity

Client and Server Contexts expose the same identity and launch information:

```ts
const program = await context.program()
const process = await context.process()
const parent = await context.parent()
const options = await context.options()

console.log(program.identity, process.identity, parent?.identity, options)
```

`name()` returns the current Process name or `null`. `parent()` returns the
visible parent Process or `null`. `isService()` reports the role of this
exact Endpoint execution context. `stop()` ends the execution context and releases the
boundary operations and registrations it owns.

The Context receives messages addressed to its Endpoint and can publish
destinationless output. Inbound messages contain `{ from, payload }`. `from`
is `null` when the sender lies outside the Context's visible scope.

## Client Context

A Client Context adds the capabilities that exist because it is running
inside a Desktop:

- `server` is the paired Server Endpoint in the same Process
- `window` is the Client Endpoint's authoritative Window
- `presentation` is this Desktop's applied representation of that Window
- `permissions` reads the executing Program's authority and can request an
  owner's decision

```ts
import { context, desktop } from "@phreshos/client"

await context.window.changeTitle("Notes")
const { size } = await desktop.viewport.snapshot()
```

`desktop` is a separate root, documented under [Desktop](/system/desktop).
Permissions belong to the Program; see [Permissions](/system/permissions).

## Server Context

A Server Context adds the paired Client Endpoint and the ability to answer
questions:

```ts
import { context } from "@phreshos/server"

const cleanup = context.answer("status.read", () => ({ ready: true }))

await context.client.waitReady()
```

`answer(event, answerer)` registers a handler for questions addressed to this
Server. It returns a cleanup that removes that handler.

The Server sees the same Program, Process, options, and
[communication](/runtime/communication) language as the Client. What differs
is the first-person position: the Server answers, the Client presents.
