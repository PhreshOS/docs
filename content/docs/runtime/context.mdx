A Context is the runtime's first-person view. It belongs to one live Endpoint
incarnation and answers questions such as: Which Process am I part of? What
launched me? Who created that Process? Which messages are addressed to me?

This is different from retaining an Endpoint handle. The handle is a permanent
address; the Context exists only while the current incarnation is executing.

## Execution identity

Client and Server Contexts expose the same identity and launch information:

```ts
const program = await context.program()
const process = await context.process()
const parent = await context.parent()
const options = await context.options()

console.log(program.identity, process.identity, parent?.identity, options)
```

`name()` returns the current Process name or `null`. `parent()` returns the
visible parent Process or `null`. `isService()` reports the role of this exact
Endpoint incarnation. `stop()` ends the incarnation and releases the boundary
operations and registrations it owns.

The Context also receives messages addressed to its Endpoint and can publish
destinationless output. Inbound messages contain `{ from, payload }`; `from`
is `null` when the sender lies outside the Context's visible scope.

## Client Context

A Client Context adds the capabilities that exist because it is running inside
a Desktop:

- `server` is the paired Server Endpoint in the same Process.
- `window` is the Client Endpoint's System-owned authoritative Window.
- `localWindow` is the representation of that Window owned by this Desktop.
- `permissions` reads current Client authority and requests an owner's decision.

```ts
await context.window.changeTitle("Notes")
await context.localWindow.raise()
```

Authoritative and local Window operations are deliberately separate. See
[Desktop](/system/desktop) for their ownership and layer rules.

## Server Context

A Server Context adds the paired `client` Endpoint and the ability to answer
questions addressed to the Server:

```ts
const cleanup = context.answer("document.read", ({ payload }) => {
  return loadDocument(payload)
})
```

`answer()` returns the cleanup for that registration. Only a Server Context can
answer because questions are always addressed to Server Endpoints.
