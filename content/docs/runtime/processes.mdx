title: Processes
description: Understand one live execution created from a Program and a Launch.

A Process is one live execution of a Program. It groups the Server and Client
Endpoints that belong to the same run and preserves the exact intent that
created them.

Its `identity`, optional Program-local `name`, `startedAt` time, launch options,
and parent never change. Its Endpoint incarnations may start and stop
independently. The Process remains addressable until it exits, and the final
live Endpoint cannot be stopped as an independent operation.

## Launch defines the run

A `Launch` decides which declared Endpoints start, whether either Endpoint is a
Service, the Client's initial Window state, and the string options shared by
both Endpoints. Omitted Endpoint choices use the Program declaration.

```ts
const process = await program.createProcess({
  name: "main",
  server: { service: true },
  client: {
    title: "Notes",
    size: { width: 900, height: 640 },
  },
  options: { workspace: "personal" },
})
```

`process.options()` returns the complete immutable option object;
`process.options(name)` returns one value. Context exposes the same options to
the running Endpoint.

A name gives the Process a stable address inside its Program. Creating another
live Process with the same name normally rejects. With `replace: true`, the
System ends the existing named Process and creates the requested replacement as
one serialized operation.

```ts
await program.createProcess({
  name: "main",
  replace: true,
  client: true,
})
```

`findOrCreateProcess()` is different: without replacement, it returns the
named Process when its resolved Launch already matches, creates it when absent,
and rejects when the name is occupied by a different Launch.

## Endpoints are permanent handles

Every Process exposes `server` and `client`, regardless of which Endpoint kinds
the Program declared or which ones are currently running. These are permanent
addresses whose `exists()` state changes as Endpoint incarnations start and
stop.

```ts
if (await process.server.exists()) {
  await process.server.ask("status")
}
```

This lets code retain an Endpoint handle and follow its lifecycle instead of
replacing the object every time execution restarts.

## Parentage records creation

`program()` returns the owner. `parent()` returns the Process whose Endpoint
created this Process, or `null` when there was no parent visible to the caller.
Parentage records origin, not ownership: both Processes still belong to their
own Programs. A retained parent handle remains meaningful after that parent
exits.

## Attached runs

`runProcess()` gives the returned async generator ownership of a temporary
Process. It yields the created Process, its output, and its exit in order:

```ts
for await (const event of program.runProcess({ server: true })) {
  if (event.event === "started") console.log(event.process.identity)
  if (event.event === "output") console.log(event.stream, event.text)
  if (event.event === "exited") console.log(event.exit)
}
```

Aborting the supplied signal, returning from the generator early, or losing
the connection that owns the run exits the Process. This makes an attached run
suitable for development and bounded jobs without inventing another Process
kind.

## Exit and observation

`exit()` ends the Process and all live Endpoints. `exited()` reports whether
that terminal transition has happened. The Process emits one `exit` event with
its status, exit code, and signal. Its Program and the System Process collection
publish the same lifecycle at their respective scopes.
