A Process is one live execution of a Program. It groups the Server and Client
Endpoints that belong to the same run and preserves the intent that created
them.

Its `identity`, optional Program-local `name`, `startedAt` time, launch
options, and parent never change. Its Endpoint execution contexts may start and
stop independently. The Process remains addressable until it exits. The
final live Endpoint cannot be stopped as an independent operation.

## Launch

A `Launch` decides which declared Endpoints start, whether either Endpoint is
a Service, the Client's initial Window state, and the string options shared
by both Endpoints. Omitted Endpoint choices use the Program definition.

```ts
const process = await program.createProcess({
  name: "main",
  server: { service: true },
  client: {
    title: "Notes",
    size: { width: 900, height: 640 },
  },
  options: { workspace: "personal" },
})
```

`server` and `client` each accept a boolean or an options object. `false`
keeps that Endpoint stopped, `true` starts it with declaration defaults, and
an object starts it with the supplied overrides. A Server object can override
`service`. A Client object can override `service`, title, header, frame,
default transaction, position, size, layer, minimized state, and maximized
state.

Launch overrides replace only the values they contain. In particular,
restarting a stopped Client with `{ client: true }` preserves its authoritative
Window state; supplying a Window value explicitly replaces that stored value.

`process.options()` returns the complete immutable option object;
`process.options(name)` returns one value. Context exposes the same options
to the running Endpoint.

A name gives the Process a stable address inside its Program. Creating
another live Process with the same name rejects, unless `replace: true` is
set. Then the System ends the existing named Process and creates the
requested replacement as one serialized operation.

```ts
await program.createProcess({
  name: "main",
  replace: true,
  client: true,
})
```

`findOrCreateProcess()` returns the named Process when its resolved Launch
already matches, creates it when absent, and rejects when the name is
occupied by a different Launch.

## Endpoints are permanent handles

Every Process exposes `server` and `client`, regardless of which Endpoint
kinds the Program declared or which ones are currently running. These are
permanent handles whose `running()` state changes as execution contexts start
and stop.

```ts
if (await process.server.running()) {
  await process.server.ask("status")
}
```

See [Endpoints](/runtime/endpoints).

## Parentage

`program()` returns the owner. `parent()` returns the Process whose Endpoint
created this Process, or `null` when there was no parent visible to the
caller. Parentage records origin, not ownership: both Processes still belong
to their own Programs. A parent handle remains available after that parent
exits.

## Attached runs

`runProcess()` gives the returned async generator ownership of a temporary
Process. It yields the created Process, its output, and its exit in order:

```ts
for await (const event of program.runProcess({ server: true })) {
  if (event.event === "started") console.log(event.process.identity)
  if (event.event === "output") console.log(event.stream, event.text)
  if (event.event === "exited") console.log(event.exit)
}
```

Aborting the supplied signal, returning from the generator early, or losing
the connection that owns the run exits the Process. `phresh dev` and
`phresh start` use this lifetime: the Process belongs to the terminal
command.

## Exit and observation

`exit()` ends the Process and all live Endpoints. `exited()` reports whether
that terminal transition has happened. The Process emits one `exit` event
with its status, exit code, and signal.

```ts
const processes = await system.process.list()
const found = await system.process.find(process.identity)
```

```sh
phresh process list
phresh process exit --process main --program notes
```

`system.process.find()` accepts a Process identity. A Program-local name is
resolved through the Program that owns it.
