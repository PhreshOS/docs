Every Process owns a Server handle and a Client handle. Their capabilities
differ because their execution environments differ, but both are Endpoints in
the same domain model.

## Server

A Server executes host-side JavaScript in one of two modes:

<Tabs items={["Command", "Worker"]}>
  <Tab value="Command">
    `startCommand` starts and supervises an operating-system process tree.
  </Tab>
  <Tab value="Worker">
    `entryFile` loads an ECMAScript module as a Worker owned by the System.
  </Tab>
</Tabs>

Both modes expose the same Server SDK. A Worker is not a security boundary and
does not have an independent working directory.

## Client

A Client executes in an iframe inside the desktop and owns one Window.
It may access its current Program and Process, paired Server, Window, desktop
preferences, read-only Appearance, uploads, fetch, Program resources, and exact
Client Services.

The Client has no general authority over the desktop or foreign Programs.
Fabricating a handle cannot expand that authority.

The iframe always permits scripts and forms through its sandbox. When the
Client's effective `all` permission is present, the sandbox also permits
same-origin access. Changing between these states requires the iframe to reload.

<Callout title="Location rules">
  The browser always loads `/program/&lt;identity&gt;/assets/`. In production the
  System serves installed Client files there. During development it proxies the
  declared HTTP(S) Client server, including its WebSocket traffic, through the
  same address. Installation still requires Client files that the System can
  copy into installed storage.
</Callout>
