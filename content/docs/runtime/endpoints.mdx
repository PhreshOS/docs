Every Process owns a permanent `ServerEndpoint` handle and `ClientEndpoint`
handle. Both implement the shared Endpoint contract; each adds only the
capabilities inherent to its execution role.

## Shared contract

An Endpoint publishes application events, exposes its outgoing traffic, and
observes `start` and `stop` transitions through `lifecycle`.

| Operation | Contract |
| --- | --- |
| `exists()` | Read whether a current incarnation exists |
| `isService()` | Read whether that incarnation declared a Service role |
| `start()` | Create a fresh incarnation |
| `stop()` | End the incarnation without implicitly ending the Process |
| `waitReady()` | Wait up to ten seconds by default for a usable incarnation |

A Client is ready when it exists. A Server must also announce readiness.
Starting rejects when the Program did not declare that Endpoint or an
incarnation is already starting or live. Stopping rejects when it would remove
the Process's final live Endpoint. Readiness rejects when the owning Process can
no longer provide a future incarnation.

## Server Endpoint

A Server executes host-side JavaScript in one of two modes:

<Tabs items={["Command", "Worker"]}>
  <Tab value="Command">
    `startCommand` starts and supervises an operating-system process tree.
  </Tab>
  <Tab value="Worker">
    `entryFile` loads an ECMAScript module as a Worker owned by the System.
  </Tab>
</Tabs>

Both modes expose the same Server SDK contract. A Worker is not a security
boundary and does not have an independent working directory.

## Client Endpoint

A Client executes in an iframe inside the Desktop and owns one Window. Its
Context provides its Program, Process, paired Server Endpoint, Window, local
Window representation, options, communication, and permission requests.

The Client may access its own Program, Processes belonging to that Program, and
Services belonging to that Program. System-wide capabilities and foreign
Programs require the `all` permission. See [Security](/system/security).

The iframe always permits scripts and forms through its sandbox. When the
Client's effective `all` permission is present, the sandbox also permits
same-origin access. Changing between these states requires the iframe to reload.

## Client assets

The browser always loads `/program/<assetId>/assets/`. In production the System
serves installed Client files there. During development it proxies the declared
HTTP(S) Client server, including WebSocket traffic, through the same address.
Installation still requires Client files that the System can copy into
installed storage.
