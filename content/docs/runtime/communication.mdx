Communication is expressed through Context, Endpoint, and Service contracts;
the transport used by an SDK does not change their meaning.

## Context

The `context` object is the executing Endpoint's communication and runtime
environment.

```ts
context.subscribe("changed", (message) => {
  console.log(message.payload)
})

context.publish("changed", { value: 1 })
```

Context subscriptions receive messages addressed to the executing Endpoint as
`{ from, payload }`. Publishing emits from that Endpoint and does not loop back
into the same Context subscription.

On the Server, `context.answer()` answers questions addressed to that Server.

```ts
context.answer("status.read", () => ({ ready: true }))
```

## Endpoint and Service handles

Use an Endpoint handle when the exact destination or source matters. Use a
Service when the stable service address matters instead of one Process
incarnation.

- `endpoint.publish()` sends directly to that Endpoint.
- `server.ask()` asks an exact Server.
- `endpoint.subscribe()` follows destinationless publications from that Endpoint.
- `endpoint.traffic` inspects directed questions, publications, and answers.

Every permanent Endpoint also has `endpoint.lifecycle`, a separate subscribable
surface for its own `start` and `stop` transitions. Application events remain
on the Endpoint root.

## Observation

Every subscribable contract follows the same three forms:

| Operation | Result |
| --- | --- |
| `subscribe(event, callback)` | Persistent registration and its cleanup function |
| `waitFor(event, timeout?)` | Promise for the next matching message |
| `events(event?, { signal, capacity }?)` | Abortable asynchronous iterator |

`waitFor()` and `ask()` use a ten-second deadline unless the caller supplies
another one. Event iterators remain live until closed, aborted, or future
delivery becomes impossible.

`endpoint.traffic` observes directed publications and questions originating
from an Endpoint. Server traffic also observes answers. Questions use
`subscribeAsks()` or `asks()`; answers use `subscribeAnswers()` or `answers()`.

## Delivery semantics

Importing an SDK or starting an Endpoint does not push state into it. Requests
read the present. Subscriptions observe future publications and do not replay an
initial value. Persistent registrations may survive temporary Endpoint absence
and end when their cleanup runs or their owning boundary is destroyed. React
state hooks compose an explicit read with a subscription without changing those
semantics.
