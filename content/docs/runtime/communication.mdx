Communication is one contract shared by Context, Endpoint, and Service
surfaces. SDK transports may differ; message meaning and lifecycle do not.

## Publications

`publish(event, payload?)` is synchronous and fire-and-forget. It returns no
delivery result, and an unavailable destination silently drops the
publication.

`context.publish()` produces destinationless output from the executing
Endpoint. `endpoint.publish()` targets that exact Endpoint, and
`service.publish()` targets the Endpoint at that Service address. An Endpoint
root subscription observes its destinationless output; `traffic` observes its
directed output.

Context receives messages addressed to its executing Endpoint:

```ts
context.subscribe("changed", message => {
  console.log(message.from, message.payload)
})

context.publish("changed", { value: 1 })
```

Context messages are `{ from, payload }`. Endpoint traffic messages are
`{ to, payload }`. An inaccessible sender or destination is represented as
`null`, never as a fabricated or partially visible handle.

## Observation

Every `Subscribable` exposes the same three operations:

| Operation | Result |
| --- | --- |
| `subscribe(event, subscriber)` | Persistent registration and its cleanup |
| `subscribe(subscriber)` | Persistent registration across correlated `{ event, message }` captures |
| `waitFor(event, timeout?)` | Promise for the next matching message |
| `events(event?, options?)` | Async iterator for one event or all correlated captures |

Event iterator options are `{ signal, capacity }`. Capacity defaults to `64`;
`Infinity` removes the queue bound. `waitFor()` uses ten seconds by default.

Subscriptions observe future messages and do not replay current state. A
persistent registration ends only when its cleanup runs or its owning boundary
is destroyed. Iteration ends when closed, aborted, or future delivery becomes
impossible.

## Questions and answers

Server Endpoints and Server Services are `Askable`:

```ts
const result = await server.ask("status.read")
const slower = await server.timeout(30_000).ask("report.create", {
  format: "pdf",
})
```

An ask rejects when its destination is known to be unavailable or stops before
answering. Once delivered, an unanswered question waits for its deadline
because a boundary cannot infer whether an answerer exists.

The executing Server registers an answerer through its Context:

```ts
const cleanup = context.answer("status.read", () => ({ ready: true }))
```

Answer outcomes are transport-neutral: `{ success: true, result }` or
`{ success: false, error }`.

## Traffic

`endpoint.traffic` observes communication originating from one Endpoint,
including destinations that an Endpoint subscription does not expose.

| Traffic contract | Additional observation |
| --- | --- |
| Endpoint and Client traffic | `subscribeAsks()` and `asks()` |
| Server traffic | `subscribeAsks()`, `asks()`, `subscribeAnswers()`, and `answers()` |

Question and answer captures contain `event`, `questionId`, and `message`. The
question message holds `{ to, payload }`; the answer message holds
`{ to, outcome }`. Ordinary traffic remains available through `subscribe()`,
`waitFor()`, and `events()`.
