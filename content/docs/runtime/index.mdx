The PhreshOS runtime is built from four components: **Program**, **Process**,
**Endpoint**, and **Service**. Together they describe what software exists,
what is running, where its code executes, and how other software reaches it.

A Program is the stable root. It can own multiple live Processes. Every
Process has one permanent Server Endpoint and one permanent Client Endpoint,
even when one of those Endpoints is not currently running.

```text
Program
└── Process
    ├── Server Endpoint
    └── Client Endpoint
```

A Service does not add another level to this tree. It is a stable address for
an Endpoint that chose to be reachable as a Service. This distinction keeps
ownership and discovery separate: the Process owns the Endpoint, while the
Service lets other code communicate with it.

Client, Server, and Node expose these components through the same Core
contracts. The environment changes how an operation reaches the System and
which authority it has; it does not change what a Program or Process means.
Within one SDK context, reaching the same entity again returns the same handle,
so reference equality and Core class checks remain meaningful.
