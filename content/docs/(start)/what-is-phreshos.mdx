PhreshOS is an open-source, server-authoritative operating system for running and
managing web-based Programs in a unified web Desktop environment, with native
agent access through shared APIs.

## Why PhreshOS?

Web technologies are among the most expressive tools for building personal
applications and internal software. They provide a rich interface model, a
large ecosystem, and a runtime available on almost every device. What they do
not provide on their own is a complete environment in which this software can
live.

A developer who wants a local application can package the web application with
its own browser and server runtime. The result can use the host machine, but
every application carries and manages that environment independently. A
developer who wants the application to remain available remotely must usually
build the surrounding infrastructure as well: authentication, persistence,
communication, synchronization, process management, and an interface through
which people or agents can reach it.

PhreshOS provides this as one shared environment for every Program. Software built with
web technologies can run on a controlled host, remain available independently
of any one browser, present its interface remotely, communicate with other
Programs, and use shared System capabilities. People reach it through the
Desktop; agents and other software reach the same underlying System through its
APIs.

## How it works

PhreshOS runs on a machine controlled by its owner. The System is the shared
foundation: it knows which software exists, what is running, and how everything
within the environment can work together. The Desktop is the graphical view of
that System, available through a browser from wherever the owner chooses to
make it accessible.

A Program is the stable software identity. Each live execution is a Process.
The Process owns one Server Endpoint and one Client Endpoint. A Service gives a
stable address to an Endpoint that chooses to be reachable.

The Server Endpoint lets a Program continue working on the host independently
of a browser. The Client Endpoint presents its interface through the Desktop.
Services allow Programs to reach one another without taking ownership of each
other's execution.

Together, these parts give every Program the same environment for execution,
communication, persistence, and remote access. People interact with that
environment through the Desktop, while agents and other software interact with
it through shared APIs.
