Appearance is the System's complete unresolved visual state. It is one
document: colors, spacing, radius, shadow, material, transaction, and wallpapers,
each with both a light and a dark branch where the value is themed.

Programs and the Desktop derive presentation from this source.
[React UI](/sdks/react-ui) interprets the visual fields it owns; wallpapers
remain System-only.

```ts
const appearance = await system.appearance.snapshot()

system.appearance.subscribe("change", next => {
  console.log(next.colors.dark.background)
})
```

`snapshot()` returns the complete immutable value. A `change` event carries
the complete replacement rather than a partial patch. `update(appearance)`
validates and atomically replaces the whole value. The executing Program
needs the `appearance` permission.

## What the document contains

Colors are a closed set: `background`, `foreground`, `default`, `primary`,
`secondary`, `success`, `warning`, `danger`, and `info`. Each theme supplies
every name.

`spacing` and `radius` are numbers in the range 6–18. Shadow geometry is
`x`, `y`, `blur`, `spread`, and `opacity`. Material is `grain`,
`grainAmount`, `backdrop`, `opacity`, `distortion`, and `saturation`.
`transaction` is `{ duration, easing }` for visual change.

Wallpapers are System upload keys, or `null`. They are themed independently
for sign-in and for the Desktop.

Theme names on a Desktop preference do not imply which colors are lighter.
Whenever behavior depends on which color is lighter or darker, derive it from
the colors themselves.

## Desktop preferences are separate

[Desktop](/system/desktop) preferences choose theme, animations, and scale
for one representation. Appearance is the shared visual source those
preferences resolve against. Changing the Desktop theme selects which themed
branch to use.
