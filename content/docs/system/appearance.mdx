`system.appearance` is the complete unresolved visual state owned by the
System. It keeps theme branches intact until one Desktop resolves the value it
needs.

## Contract

| Operation | Result |
| --- | --- |
| `snapshot()` | Complete immutable Appearance |
| `subscribe("change", subscriber)` | Future complete replacements |
| `waitFor("change")` | Next complete replacement |
| `events("change")` | Stream of complete replacements |
| `update(appearance)` | Validate and atomically replace Appearance |

Clients may read Appearance. Updating it requires `appearance` or `all`.

## Values

| Field | Value |
| --- | --- |
| `background`, `foreground`, `primary`, `secondary`, `success`, `warning`, `danger`, `info` | Explicit light and dark colors |
| `spacing`, `radius` | One shared numeric value |
| `shadow` | Explicit light and dark outer shadow values |
| `surface` | Explicit light and dark Surface material |
| `signInWallpaper`, `desktopWallpaper` | Explicit light and dark URLs or `null` |

Surface material contains `grain`, `grainAmount`, `backdrop`, `opacity`,
`distortion`, and `saturation`.
Shadow is independent of Surface material and contains `x`, `y`, `blur`,
`spread` (CSS pixels), and `opacity`.
`appearanceLimits` publishes the inclusive supported range for every numeric
value. `standardAppearance` is the complete environment-neutral default, and
`createAppearanceSnapshot()` creates a deeply immutable snapshot.

| Value | Inclusive range |
| --- | --- |
| `spacing`, `radius` | `6–18` |
| `shadow.x`, `shadow.y` | `-48–48` |
| `shadow.blur` | `0–96` |
| `shadow.spread` | `-24–24` |
| `shadow.opacity` | `0–1` |
| `grain`, `grainAmount`, `opacity` | `0–1` |
| `backdrop` | `0–24` |
| `distortion` | `0–140` |
| `saturation` | `1–2.6` |

Each color is an independent CSS value with explicit light and dark branches.

| Color | Role | Light default | Dark default |
| --- | --- | --- | --- |
| `background` | Base background and surfaces | `#ffffff` | `#121a21` |
| `foreground` | Text and icons | `#183447` | `#edf8fc` |
| `primary` | Main actions, selection, and emphasis | `#4c9cff` | `#4c9cff` |
| `secondary` | Alternative emphasis | `#8b5cf6` | `#a78bfa` |
| `success` | Successful or positive states | `#16a34a` | `#4ade80` |
| `warning` | Caution | `#d97706` | `#fbbf24` |
| `danger` | Errors and destructive actions | `#dc2626` | `#f87171` |
| `info` | Informational states | `#0891b2` | `#22d3ee` |

React UI's `useColor()` derives `subtle`, `soft`, `base`, `strong`, and `intense`
treatments from a resolved color. Desktop text remains derived from
`foreground`; status colors distinguish backgrounds, borders, and indicators.

Standard spacing is `12`, radius is `10`, and wallpapers are `null`. Surface
material uses a backdrop blur of `12`, opacity of `0.2` in the light branch and
`0.35` in the dark branch, neutral saturation, and no grain or distortion.

Both shadow branches default to `{ x: 0, y: 8, blur: 24, spread: 0, opacity: 0.16 }`.
Surface never consumes or renders this setting. A component that owns elevation
may resolve it independently; shadow is not part of the Surface material contract.

## Theme resolution

`desktop.preferences.snapshot()` returns effective `{ theme, animations }`.
Updates accept a direct `light` or `dark` theme, a boolean animation choice, or
`default` to follow the native environment. At least one preference is required.

A consumer combines the Appearance snapshot with the effective theme and
resolves only the property it needs.

Theme names select branches; they do not determine a color's brightness. When
a visual treatment depends on lightness, compare the resolved colors themselves.

## Client color scheme

The System sets the effective `color-scheme` on each Client iframe when it is
created. The Client HTML document declares support for both schemes:

```html
<meta name="color-scheme" content="light dark" />
```

This lets the browser choose built-in controls and the initial canvas before
React mounts; no hook races the first paint.

## Visual language

`@phreshos/react-ui` is the visual language used inside the Desktop and
available to Programs. `AppearanceProvider` supplies Appearance and Theme
without rendering a container.

Its direction is **freshlism**: simple, clear, responsive, and free from
unjustified visual or DOM hierarchy. Containers can provide Grid or Flex
layout, including arranging, aligning, and spacing children. Avoid a wrapper
when its only child can carry the same properties and behavior without
changing the result. Keep a separate container when its layout or behavior
requires the parent-child relationship.
