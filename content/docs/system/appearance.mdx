Appearance is the System's complete unresolved visual state. It is one
document: colors, spacing, radius, shadow, material, transaction, and wallpapers,
each with both a light and a dark branch where the value is themed.

Programs and the Desktop derive presentation from this source.
[React UI](/sdks/react-ui) interprets the visual fields it owns; wallpapers
remain System-only.

```ts
const appearance = await system.appearance.snapshot()

system.appearance.subscribe("change", next => {
  console.log(next.colors.dark.background)
})
```

`snapshot()` returns the complete immutable value. `update(partial)` recursively
merges the supplied fields into the current Appearance, validates the resolved
result, and commits it atomically. A complete Appearance is also a valid update.
A `change` event carries the complete resolved snapshot rather than the partial
input. The executing Program needs the `appearance` permission.

Core exports `defaultAppearance`, `appearanceLimits`,
`createAppearanceSnapshot()`, and `applyAppearanceUpdate()`. Independent tools
can therefore create, update, and validate Appearance values without first
connecting to a System.

## What the document contains

Colors are a closed set: `background`, `foreground`, `default`, `primary`,
`secondary`, `success`, `warning`, `danger`, and `info`. Each theme supplies
every name.

`spacing` and `radius` are numbers in the range 6–18. Shadow geometry is
`x`, `y`, `blur`, `spread`, and `opacity`. Material is `grain`,
`grainAmount`, `backdrop`, `opacity`, `distortion`, and `saturation`.
`transaction` is `{ duration, easing }` for visual change.

| Value | Accepted range |
| --- | ---: |
| Shadow `x`, `y` | `-48`–`48` |
| Shadow `blur` | `0`–`96` |
| Shadow `spread` | `-24`–`24` |
| Shadow `opacity` | `0`–`1` |
| Material `grain`, `grainAmount`, `opacity` | `0`–`1` |
| Material `backdrop` | `0`–`24` |
| Material `distortion` | `0`–`140` |
| Material `saturation` | `1`–`2.6` |
| Transaction `duration` | `0`–`60000` milliseconds |

Transaction easing accepts `linear`, `ease`, `ease-in`, `ease-out`,
`ease-in-out`, or a four-number cubic Bézier tuple. `appearanceLimits`
exports these numeric bounds for editors and validation interfaces.

The current `defaultAppearance` uses spacing `12`, radius `10`, and a
`120ms ease-out` transaction. Its light and dark Material branches are:

```ts
{
  light: {
    grain: 0.04,
    grainAmount: 0.95,
    backdrop: 5,
    opacity: 0.8,
    distortion: 0,
    saturation: 1.66,
  },
  dark: {
    grain: 0.03,
    grainAmount: 0.95,
    backdrop: 12,
    opacity: 0.8,
    distortion: 0,
    saturation: 1.77,
  },
}
```

`signInWallpaper` and `desktopWallpaper` each contain independent `light` and
`dark` values. A non-null value is the opaque key returned by
`system.uploads.write()` for a supported image, video, or HTML upload. `null`
selects the bundled wallpaper for that theme; both defaults are `null`.

```ts
const uploaded = await system.uploads.write(file)

await system.appearance.update({
  desktopWallpaper: {
    dark: uploaded.file,
  },
})
```

Images use cover sizing; videos autoplay muted, loop, and play inline. HTML
runs in a sandboxed iframe without top-level navigation or network access.
Uploads are limited to 50 MiB and support common browser image formats,
`mp4`, `ogg`, `ogv`, `webm`, and `html`. Wallpaper values are upload keys, not
URLs or CSS colors; a self-contained SVG or HTML upload can represent a solid
color.

Theme names on a Desktop preference do not imply which colors are lighter.
Whenever behavior depends on which color is lighter or darker, derive it from
the colors themselves.

## Desktop preferences are separate

[Desktop](/system/desktop) preferences choose theme, animations, and scale
for one representation. Appearance is the shared visual source those
preferences resolve against. Changing the Desktop theme selects which themed
branch to use.
