---
title: Authentication
description: Owner Sessions and the browser Connections they authorize.
---

A Connection is one live browser connection to the System. A Session is a
persistent authentication grant. Each Connection has either no Session or one
Session. A Session may authorize any number of Connections.

These are first-class domain objects with stable public identities. They
describe browser authentication. The owner-local Node gateway is an external
trusted transport and is not a value in either domain.

## Connection

A Connection exists for as long as the underlying browser connection.
`connected()` reports whether it remains live. `session()` returns its
currently attached Session, or `null`.

```ts
const connection = await desktop.connection()
const session = await connection.session()

console.log(connection.identity, session?.identity)
```

`signIn()` creates and attaches a new Session. It rejects if the Connection
is already signed in, or if the Connection no longer exists. A
`sessionChange` event carries the new Session or `null`. `disconnect` is the
terminal Connection event.

After the Connection ends, `connected()` is `false` and `session()` is
`null`.

At System scope, `system.authentication.connections()` and `connection()`
expose live visible Connections. The Authentication handle emits
`connectionCreate` and `connectionDisconnect`.

## Session

A Session survives individual Connection lifetimes. `valid()` reports whether
it can authorize a Connection. `connections()` returns its currently attached
live Connections.

```ts
const connections = await session.connections()

session.subscribe("connectionAttach", connection => {
  console.log("Attached", connection.identity)
})
```

The Session emits `connectionAttach` and `connectionDetach` as its membership
changes. `signOut()` ends the Session and detaches every Connection using it.
It rejects if the Session no longer exists. The terminal `end` event contains
a reason of `"signedOut"` or `"expired"`.

After the Session ends, `valid()` is `false` and `connections()` is empty.

`system.authentication.sessions()` and `session()` expose visible valid
Sessions. The Authentication handle emits `sessionCreate` and `sessionEnd`.
The end event contains both the Session and its reason.

## Owner credentials

`system.authentication.state()` returns the configured public username, or
`null` before the owner has credentials. `requirements()` returns the username
and password length bounds enforced by that System.

`setCredentials()` replaces the complete username and password used for later
sign-ins. Existing Sessions remain valid. A caller can end one Session with
`session.signOut()` or explicitly end all Sessions with
`system.authentication.signOutAllSessions()`.

## Validity

The raw Session token exists only on the browser Client. The System stores a
hash together with the Session's public identity.

A Session remains valid indefinitely while at least one Connection is
attached. After its final normal disconnection, it remains valid for 24
hours. If a later authorization attempt finds it older than that limit, the
Session expires and is removed. Explicit sign-out removes it immediately.

Signing out changes attached Connections from authorized to unauthorized. It
does not close their WebSockets. Connection transport and Connection
authorization are separate lifecycles.

A Program needs the `authentication` permission to read or change owner
authentication and to access every Connection and Session. That permission
also grants `desktopConnection`, which gives a Client access to the containing
Desktop Connection and its attached Session.
