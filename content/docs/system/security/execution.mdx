---
title: Endpoint Execution
description: Runtime containment for Server and Client Endpoints.
---

An Endpoint's execution mode determines the ambient authority of its runtime.
It does not change the Endpoint contract or grant authority through the System
API.

## Server execution

A Server declaration chooses exactly one execution mode:

- `command` runs a supervised operating-system process with that process's
  host capabilities.
- `worker` runs an ECMAScript module in a Node.js Worker while retaining host
  capabilities.
- `sandbox` runs a bundled module in a capability-contained JavaScript runtime
  with no ambient host access.

All three modes expose the same Server SDK and Endpoint contract. A sandbox
Server reaches the outside environment only through the System capabilities
available to its Program. A command or worker Server may also use the host
capabilities provided directly by its runtime.

## Client execution

A Client declaration uses `sandbox` to choose how its browser document runs.
The default is `true`, which applies an iframe sandbox that permits scripts and
forms without granting normal same-origin authority.

```ts
client: {
  location: "dist/client",
  sandbox: true,
}
```

Setting `sandbox: false` removes the iframe's sandbox attribute and gives the
document the authority of an ordinary same-origin browser frame.

```ts
client: {
  location: "dist/client",
  sandbox: false,
}
```

In either mode, the Client uses the same Client SDK and Endpoint contract.
Browser containment determines the document's ambient browser capabilities;
System API access remains governed by the Program's authority.
