title: Network

`system.network` gives every SDK the same two outbound network capabilities.
It preserves the web platform contracts: Fetch returns a standard `Response`,
and WebSocket returns a standard `WebSocket`. PhreshOS controls authority and
lifetime without inventing another request or socket model.

## Fetch

```ts
const response = await system.network.fetch("https://api.example.com/items", {
  headers: { accept: "application/json" },
})

const items = await response.json()
```

The operation accepts `RequestInfo | URL` and an optional `RequestInit`.
Supplying a `Request` preserves its method, headers, body, and abort signal.
Client and Server SDKs cross their System boundaries. A trusted Node connection
may execute the request locally when that preserves the same observable result.

## WebSocket

```ts
const socket = await system.network.websocket("wss://example.com/events")

socket.addEventListener("message", event => {
  console.log(event.data)
})
```

The returned socket uses the standard browser-compatible lifecycle, methods,
properties, and events. The acquisition is asynchronous because a Client may
need to cross the System boundary before receiving that socket.

Server and Node sockets close when their owning execution Context or System
connection ends. A Client-owned socket follows the browser frame that received
it.

## Program authority

A Client or Server Endpoint needs a `network` scope covering the requested URL
or the applicable `all` fallback. HTTP and WebSocket schemes are distinct.
Permission failure rejects the operation before the value is returned.

The permission governs `system.network.fetch()` and
`system.network.websocket()`, not network capabilities supplied directly by
the browser or Server execution environment. Once a `Response` or WebSocket
has been returned, changing the permission does not retroactively revoke that
value. See [Permissions](/system/permissions) for the scope grammar.
