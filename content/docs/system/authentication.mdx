A Connection is one live browser connection to the System. A Session is a
persistent authentication grant. Each Connection has either no Session or one
Session, while a Session may authorize any number of Connections.

These are first-class domain objects with stable public identities and
canonical handles. They describe browser authentication; the owner-local Node
gateway is an external trusted transport and is not a value in either domain.

## Connection

A Connection exists for exactly as long as the underlying browser connection.
`connected()` reports whether it remains live, and `session()` returns its
currently attached Session or `null`.

```ts
const connection = await desktop.connection()
const session = await connection.session()

console.log(connection.identity, session?.identity)
```

`signIn()` creates and attaches a new Session. It rejects if the Connection is
already signed in. A `sessionChange` event carries the new Session or `null`;
`disconnect` is the terminal Connection event.

At System scope, `system.connection.list()` and `find()` expose live visible
Connections. The collection emits `create` and `disconnect` with the affected
Connection handle.

## Session

A Session survives individual Connection lifetimes. `valid()` reports whether
it can still authorize a Connection, and `connections()` returns its currently
attached live Connections.

```ts
const connections = await session.connections()

session.subscribe("connectionAttach", connection => {
  console.log("Attached", connection.identity)
})
```

The Session emits `connectionAttach` and `connectionDetach` as its membership
changes. `signOut()` ends the Session explicitly and detaches every Connection
using it. The terminal `end` event contains a reason of `"signedOut"` or
`"expired"`.

`system.session` lists and finds visible valid Sessions and emits `create` and
`end`. The System-level end event contains both the Session and its reason.

## Session validity

The raw Session token exists only on the browser Client. The System stores a
SHA-256 hash together with the Session's public identity and its most recent
normal disconnection time.

A Session remains valid indefinitely while at least one Connection is
attached. After its final normal disconnection, it remains valid for 24 hours.
If a later authorization attempt finds it older than that limit, the Session
expires and is removed. Explicit sign-out removes it immediately.

Signing out changes attached Connections from authorized to unauthorized; it
does not close their WebSockets. Connection transport and Connection
authorization are separate lifecycles.

After disconnection, `connection.connected()` is `false` and
`connection.session()` is `null`. After a Session ends, `session.valid()` is
`false` and `session.connections()` is empty. Operations that require the live
entity reject once its terminal lifecycle has completed.
