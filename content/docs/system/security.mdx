PhreshOS has one owner rather than a collection of user accounts. Initial setup
registers that owner and then closes registration. Later desktop sessions sign
in as the same owner.

The System provides no independent recovery authority above the owner's chosen
authentication method.

## Client isolation

A Client receives only the handles and capabilities allowed by its boundary. It
cannot enlarge authority by fabricating an identity or message. An inaccessible
handle behaves like a nonexistent one, and a hidden sender or destination is
represented as `null`.

## Permissions

Permissions come from the System's finite catalog. Programs cannot invent
private permission strings. The current catalog contains the value-less `all`
permission, declared as:

```ts
permissions: {
  all: true
}
```

`true` resolves to the canonical empty list because `all` has no selectable
values. When present, it grants every available Client permission, permits
`program.permissions`, allows Desktop preference updates, and adds
`allow-same-origin` to the Client iframe. Without it, Clients may read Desktop
preferences but cannot change them. A Client may address Services belonging to
its own Program; Services belonging to another Program require `all`.

<Callout type="info">
  Self-hosting means authority and recovery remain with the machine owner. Keep
  the System home and authentication material backed up according to your own
  operational policy.
</Callout>
