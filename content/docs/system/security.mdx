PhreshOS security separates three questions. Authentication establishes which
browser Connections belong to the System owner. Permissions determine which
System capabilities a Program may see and use. The Server execution mode
determines which capabilities its runtime has independently of the System
API.

A browser Connection and a Program are different authorities. One Session may
authorize several Connections. A Program's permission state governs System
access for every Endpoint it owns.

Initial setup signs up the owner. Later browser Connections sign in by
attaching a Session.

A Server declaration chooses exactly one execution mechanism:

- `command` — a supervised operating-system process with that process's host
  capabilities
- `worker` — an ECMAScript module in a Node.js Worker, still on the host
- `sandbox` — a bundled module in a capability-contained JavaScript runtime
  with no ambient host access

The three mechanisms share the Server SDK and Endpoint contract. A sandbox
Server's only outside capabilities are the permission-constrained System
operations. See [Program configuration](/sdks/core/program-configuration).
