Security begins with one System owner and structural authority boundaries.
Initial setup registers the owner and closes registration; later Desktop
sessions authenticate as that owner.

The System provides no independent recovery authority above the owner's chosen
authentication method.

## Client authority

A Client can access its own Program, that Program's Processes and resources,
Services belonging to that Program, read-only Appearance, Desktop surface and
preferences, and its Context capabilities. It cannot enlarge authority by
fabricating an identity or message. An inaccessible handle behaves like a
nonexistent one; a hidden sender or destination is represented as `null`.

## Permissions

Permissions come from the closed Core catalog. A Program cannot invent a
permission name or a value outside that permission's finite value domain.

Immutable initial grants are declared under `client.permissions`. Stored user
grants belong to the Program. Permission checking considers the declaration
first and then the stored grant.

The current catalog contains the value-less `all` permission:

```ts
permissions: {
  all: true
}
```

`true` is assignment and request shorthand for the permission's default value.
For `all`, it resolves to the canonical empty list because the permission has no
selectable values. Arrays are unordered sets.

When present, `all` grants every System capability, permits
`program.permissions`, allows Appearance and Desktop preference updates, and
adds `allow-same-origin` to the Client iframe. Activating or removing that iframe
capability requires a reload.

`context.permissions.get()` returns the stored user value.
`context.permissions.request()` returns `{ permission, needReload }`; it returns
an existing sufficient grant without prompting. Otherwise, the owner may grant
the request for the current Process, store it for the Program, deny it, or leave
it unresolved. Requests wait for up to two minutes by default, and `timeout()`
selects another deadline.

`needReload` is derived from the effective permission transition when the
request is resolved; it is not stored as permission state. `program.permissions`
can set or remove stored grants authoritatively and is itself available only
with `all`.

Asynchronous operations reject with `Execution is not permitted` when authority
is missing. Synchronous operations that cannot report failure remain silent.
