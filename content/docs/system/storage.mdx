PhreshOS separates persistence by meaning. `Storage` represents directories and
files within a filesystem boundary. `uploads` is a flat collection of public
files. Program store and SQL provide structured persistence without pretending
to be filesystems.

## Selecting a location

A `Storage` value is a directory location. A `StorageFile` is a file location.
`navigate()` and `file()` only derive new handles; they perform no filesystem
access and preserve the boundary of the Storage from which they came.

```ts
const reports = system.storage.navigate("Documents", "reports")
const today = reports.file("today.json")

await reports.create()
await today.write({ complete: true })
```

This distinction lets code construct a path before deciding whether to read,
write, watch, move, or delete it. `name()` and `path()` return the selected
location. `stat()` returns metadata or `null` when the entry does not exist.

## Directories and files

A directory can be created, listed, copied, moved, deleted, or cleared. Its
`space()` operation reports filesystem capacity, available bytes, and used
bytes. `watch()` yields ordered `change` and `rename` events until its signal is
aborted or iteration ends.

```ts
for await (const change of reports.watch({ recursive: true })) {
  console.log(change.event, change.path)
}
```

A file can be read as a stream, bytes, UTF-8 text, or parsed JSON. Byte reads
accept an offset and length. `write()` replaces the file atomically and permits
overwrite by default; `append()` extends it. Copying and moving reject an
existing destination unless `overwrite: true` is supplied.

Writable content may be JSON data, a `Blob`, an `ArrayBuffer`, an
`ArrayBufferView`, or a `ReadableStream<Uint8Array>`. The contract deliberately
does not accept an untyped `unknown` value.

## Native and Program boundaries

`system.storage` begins at the operating-system user's home directory. It is an
entry point, not a containment boundary: an absolute path may select another
native location. A Client needs a `storage` scope covering the operation and
path it actually uses.

Every Program exposes `data` and `cache` through the same Storage contract.
Their implementations are contained within Program-owned roots and cannot
escape through parent segments or symbolic links. `data` is durable;
`cache` is disposable. All Processes belonging to the Program share both.

```ts
const settings = program.data.file("settings.json")
const cachedIndex = program.cache.file("search", "index.bin")
```

Client access follows Program visibility. Returning any native absolute path
through `path()` additionally requires a matching Storage permission.

## Uploads

`system.uploads` stores public files under opaque generated keys. It is flat by
design: there is no directory navigation, listing, deletion, or clearing
contract.

```ts
const upload = await system.uploads.write(imageBlob)

console.log(upload.file, upload.size, upload.modifiedAt)
const bytes = await system.uploads.bytes(upload.file)
```

`write()` accepts the same `WritableContent` convention as Storage and returns
the generated file key together with size and last-modified time. `stat()`
returns that file metadata or `null`. Existing uploads can be read as streams,
bytes, text, or JSON. A Client needs `uploads` to create one; reading a known
public upload does not require that permission.

## Structured Program state

`program.store` is persistent key-value state. Values can be read, tested,
replaced, deleted, or cleared. `set(key, value, ttl?)` can attach an expiration
time in milliseconds.

```ts
await program.store.set("draft", { title: "Welcome" })
const draft = await program.store.get("draft")
```

`program.database` is a writable SQLite database. `program.logs` exposes the
same query shape over read-only captured Client and Server output. Both accept
tagged SQL templates or a SQL string with bound values.

Production System state lives beneath `~/.phreshos` by default.
`PHRESHOS_HOME` selects another root for the System database, installed
Programs, Program resources, uploads, credentials, logs, and local gateway.
