PhreshOS separates persistence by meaning. `Storage` represents directories
and files within a filesystem boundary. `uploads` is a flat collection of
public files. Program store and SQL provide structured persistence.

## Selecting a location

A `Storage` value is a directory location. A `StorageFile` is a file
location. `navigate()` and `file()` only derive new handles; they perform no
filesystem access and preserve the boundary of the Storage from which they
came.

```ts
const reports = system.storage.navigate("Documents", "reports")
const today = reports.file("today.json")

await reports.create()
await today.write({ complete: true })
```

`name()` and `path()` return the selected location. `stat()` returns metadata
or `null` when the entry does not exist.

## Directories and files

A directory can be created, listed, copied, moved, deleted, or cleared.
`space()` reports filesystem capacity, available bytes, and used bytes.
`watch()` yields ordered `change` and `rename` events until its signal is
aborted or iteration ends.

```ts
for await (const change of reports.watch({ recursive: true })) {
  console.log(change.event, change.path)
}
```

A file can be read as a stream, bytes, UTF-8 text, or parsed JSON. Byte reads
accept an offset and length. `write()` replaces the file atomically and
permits overwrite by default; `append()` extends it. Copying and moving
reject an existing destination unless `overwrite: true` is supplied.

Writable content may be JSON data, a `Blob`, an `ArrayBuffer`, an
`ArrayBufferView`, or a `ReadableStream<Uint8Array>`.

## Native and Program boundaries

`system.storage` begins at the operating-system user's home directory. It is
an entry point, not a containment boundary: an absolute path may select
another native location.

A Program needs a `storage` scope covering every native operation and path it
uses. An owner-local Node connection runs native storage in the Node process.

Every Program exposes `data` and `cache` through the same Storage contract.
Their implementations are contained within Program-owned roots. `data` is
durable; `cache` is disposable. All Processes belonging to the Program share
both.

```ts
const settings = program.data.file("settings.json")
const cachedIndex = program.cache.file("search", "index.bin")
```

Program `data` and `cache` follow Program visibility. Returning any native
absolute path to a Program through `path()` requires a matching `storage`
scope.

A storage permission value is a path, optionally prefixed with
`read,write,delete` operations. A bare path grants all three. A recursive
suffix `/**` must be the final segment.

## Uploads

`system.uploads` stores public files under opaque generated keys. It is flat:
there is no directory navigation, listing, deletion, or clearing contract.

```ts
const upload = await system.uploads.write(imageBlob)
const bytes = await system.uploads.bytes(upload.file)
```

A Program needs the `uploads` permission to create an upload. Keys have the
form `uuid.ext`. Wallpapers in Appearance are upload keys.

## Store and SQL

`program.store` is key-value state with optional expiry. `program.database`
is writable SQLite. `program.logs` is read-only SQL over captured Endpoint
output. Each `query` runs one statement.

```ts
await program.store.set("draft", { title: "Untitled" })
const rows = await program.logs.query("SELECT content FROM logs WHERE kind = ?", ["error"])
```
