Permissions describe which System capabilities a Program may access. A Program
declares them, the System stores and enforces them as Program state, and that
state applies to every Client and Server Endpoint the Program owns.

Permissions constrain the System API. They do not remove capabilities granted
directly by an execution environment: Client code retains browser APIs, while
`command` and `worker` Servers retain their host capabilities. A `sandbox`
Server has no ambient host access, so its only outside capabilities are the
permission-constrained System operations.

A permission also defines which domain handles exist within the Program's
visible scope. Hidden Programs, Services, Connections, and Sessions stay
opaque. Collection `list()` operations return only visible handles. `find()`
returns `null` when an identity is absent or inaccessible. Relationships and
events apply the same filter.

Without additional authority, an Endpoint can reach its own Program, that
Program's Processes and resources, and the Services covered by an explicit
`services` grant. A Client can also read its containing Desktop's viewport and
effective preferences. Permissions extend that starting scope; they do not
replace it.

Lookup and direct access have deliberately different failure shapes. A lookup
cannot reveal whether a hidden identity exists, so it returns `null`. A direct
capability whose target is already known—such as changing Appearance or asking
for the containing Desktop Connection—rejects when the caller lacks authority.

## The permission value

Each permission stores one of three states:

- an array is a granted canonical value
- `false` is an explicit denial
- `null` or absence provides no exact decision

For a valued permission, an empty array grants its complete domain. A
non-empty array grants only the selected values. For a value-less permission,
the empty array is its canonical granted value. `true` is shorthand for the
permission's default grant when declaring, setting, or requesting it.

An exact permission assignment takes priority over `all`.

## Catalog

| Permission | What it grants |
| --- | --- |
| `services` | Every Service, or every Service using selected Process names |
| `programs` | Every Program, or selected Programs, including their Processes, Endpoints, Windows, and resources |
| `layers` | Every restricted Client Window layer, or selected `under`, `over`, `wallpaper`, and `start-menu` layers |
| `network` | Every System network target, or selected URL scopes |
| `storage` | Every native path and operation, or selected operation-and-path scopes |
| `uploads` | Creation of public uploads |
| `appearance` | Replacement of System Appearance |
| `desktopPreferences` | Changes to Desktop preferences |
| `desktopConnection` | This Desktop's Connection and its attached Session |
| `connections` | Every Connection and Session; also grants `desktopConnection` |
| `all` | Fallback authority for capabilities without an exact assignment, plus unrestricted System capabilities |

`services` is independent from `programs`. A selected value grants every
Service whose Process uses that name, without revealing its Program or other
resources. `connections` includes `desktopConnection`.

Program creation, force-creation, `program.permissions` administration, and
`system.shell()` require `all`. Effective `all` also permits same-origin
access for the Program's Client iframe.

## Declaring, inspecting, and requesting

A Program declares initial values in `phresh.config.ts`. Those declarations
are written into authoritative storage at creation and installation. Each
declared entry replaces that exact stored permission; omitted entries remain
unchanged. Declarations accept `true` or a value list; denial and removal are
runtime administration decisions made through the permission API.

```ts
permissions: {
  network: ["https://api.example.com"],
  uploads: true,
}
```

`program.permissions` is the administration API: `get`, `all`, `allows`,
`set`, and `delete`. `set()` accepts `true`, a value list, or `false`;
`delete()` removes the exact assignment so fallback authority can apply again.
Those operations require `all`.

The Client Context exposes the executing Program's stored assignment and lets
it ask the owner to grant more:

```ts
const allowed = await context.permissions.allows("network", ["https://api.example.com"])

if (!allowed) {
  await context.permissions.request("network", ["https://api.example.com"])
}
```

`get` returns the stored assignment without applying fallback authority.
`allows` reports whether the stored permission permits the requested
capability. `request` prompts the owner, replaces the stored permission, and
returns that canonical value. `timeout(milliseconds)` selects another
deadline for the prompt. The default request deadline is two minutes. Approval
returns the canonical granted list, denial returns `false`, and dismissal or a
deadline returns `null`.

Every `request()` opens a decision; it does not silently succeed because the
same or broader permission is already stored. A request requires a live Client
Endpoint because the owner decision is presented through the Desktop, and one
Client Process can have only one permission request pending at a time.

## Window layer authority

The ordinary `window` layer needs no layer permission. Selecting `under`,
`over`, `wallpaper`, or `start-menu` requires `layers` coverage. This applies
when a Program creates a Process, starts a Client Endpoint, or stores a launch
that explicitly selects one of those layers. Omitting `layer` continues through
the declaration or existing authoritative Window value.

## Network and Storage values

A network value names an explicit HTTP or WebSocket region:

```ts
permissions: {
  network: [
    "https://api.example.com",
    "https://*.example.com/v1/**",
    "http://localhost:*",
    "wss://events.example.com/**",
  ],
}
```

The scheme is part of the grant. `*.` replaces complete leading host labels,
`:*` covers every port, and a final `/**` includes a path subtree. Query and
fragment text do not expand or narrow authority.

A Storage value combines operations with a native path:

```ts
permissions: {
  storage: [
    "Documents/report.json",
    "read:Documents/**",
    "read,write:Downloads/**",
  ],
}
```

A bare path grants `read`, `write`, and `delete`. A final `/**` includes the
named path and its descendants. Relative paths begin at `system.storage`; an
absolute path keeps its native meaning. Deriving a handle with `navigate()` or
`file()` performs no access. The permission is checked when an operation reads,
writes, watches, or removes the selected native location.
