The System is the authority behind PhreshOS. It owns software identity and
execution, routes communication, persists state, controls access to the host,
and decides which Program capabilities are visible. A Desktop represents that
state graphically.

The `system` object is the common entry point in Client, Server, and Node.
Client and Server Endpoints use the permission state of their Program; an
owner-local Node connection is trusted. The capability names and returned
domain handles remain the same.

```ts
const programs = await system.program.list()
const processes = await system.process.list()

console.log(programs.length, processes.length)
```

`system.program` and `system.process` are observable collections.
`system.authentication` owns the System's public authentication state and the
observable Connection and Session registries. Each returns only the domain
objects visible to the caller.

`system.storage`, `system.uploads`, `system.appearance`, and `system.network`
expose persistent and host capabilities. `system.service` discovers available
Endpoint Services and prepares stable address handles. `system.shell()` runs a command whose lifetime
is owned by its returned iterator. `system.execute()` is the JSON form of
selected operations, documented under [Execute](/sdks/core/execute).

External Node tools and the CLI connect through an owner-local gateway. On
POSIX it is a Unix-domain socket; on Windows it is an owner-created named
pipe. This gateway is an external trusted transport, not a browser Connection
or an authentication Session.
