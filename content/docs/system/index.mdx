The System is the authority behind PhreshOS. It owns software identity and
execution, routes communication, persists state, controls access to the host,
and decides which Program capabilities are visible. A Desktop represents that
state graphically, but it does not become a second authority.

The `System` contract is the common entry point in Client, Server, and Node.
Each environment reaches it differently and may have different authority, yet
the capability names and returned domain handles remain the same.

```ts
const programs = await system.program.list()
const processes = await system.process.list()

console.log(programs.length, processes.length)
```

## One capability root

`system.program`, `system.process`, `system.connection`, and `system.session`
are observable collections. They find and list the domain objects currently
visible to the caller and publish their System-wide lifecycle events.

`system.storage`, `system.uploads`, `system.appearance`, and `system.network`
expose persistent and host capabilities. `system.service(key)` creates a stable
communication address, while `system.shell()` runs a command whose lifetime is
owned by its returned iterator.

External Node tools and the CLI connect through an owner-local gateway. On
POSIX it is a Unix-domain socket; on Windows it is an owner-created named pipe.
This gateway is an external trusted transport, not a browser Connection or an
authentication Session.
