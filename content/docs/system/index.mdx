The System is the authoritative runtime. It owns Program and Process lifecycle,
communication routing, authentication, persistence, appearance, and access to
host capabilities. The Desktop represents that state graphically.

## Contract

| Member | Capability |
| --- | --- |
| `program` | System-wide Program collection and lifecycle events |
| `process` | System-wide Process collection and lifecycle events |
| `storage` | Native filesystem access |
| `uploads` | Flat System-owned upload collection |
| `appearance` | Read and replace authoritative Appearance |
| `service(key)` | Stable communication address for one Endpoint Service |
| `forceCreateProgram(source)` | Replace one runtime Program without removing installed resources |
| `fetch(input, init?)` | Outbound web request |
| `websocket(url, protocols?)` | Outbound standard WebSocket connection |
| `shell(command, options?)` | Owned operating-system command stream |

Client, Server, and Node implement this same contract. Authority may reject an
operation; it does not replace the contract with a narrower shape.

## Local connection

External Node tools and the CLI reach the running System through an owner-local
gateway: a Unix-domain socket with owner-only permissions on POSIX systems or an
owner-created named pipe on Windows. It opens no network port.

The gateway is a connection mechanism, not a public domain. Node and the CLI
use ordinary System contracts through it; code that owns a connection adds only
`disconnect()` to end that connection's lifetime.
