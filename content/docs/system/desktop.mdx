A Desktop is one graphical representation of the System. The System owns the
authoritative state of each Client Window. The Desktop owns the measurements,
pointer interaction, iframe, animation, and temporary presentation needed to
show it on one screen.

The same Window state can be represented by more than one Desktop. The Client
Endpoint's `window` handle addresses the authoritative state. Its Context's
`localWindow` handle addresses the representation owned by the current
Desktop.

Client code reaches the containing Desktop as a separate root:

```ts
import { context, desktop } from "@phreshos/client"
```

## Viewport and preferences

`desktop.viewport` exposes the current workspace size in CSS pixels and emits
a complete `{ size }` snapshot when it changes.

`desktop.preferences` exposes the effective theme, animation choice, and
scale for this Desktop. Theme names such as `light` and `dark` do not imply
actual color luminance; colors come from [Appearance](/system/appearance).
Scale is a multiplier between `0.5` and `2`, defaulting to `1`. A preference
update may set `theme` or `animations` to `"default"` to follow the native
environment. Setting `scale` to `"default"` restores the default multiplier of
`1`.

```ts
const { size } = await desktop.viewport.snapshot()
const preferences = await desktop.preferences.snapshot()

await desktop.preferences.update({ theme: "dark" })
```

`desktop.connection()` returns the browser Connection carrying this Desktop.
The executing Program needs `desktopConnection` or `connections`.

## Authoritative Window

Every Client Endpoint has one permanent `window` handle. Title, header,
geometry, minimized state, maximized state, front state, and layer belong to
the System. Reads return those authoritative values. Mutations change them
and publish the matching Window event.

```ts
await context.window.setGeometry({
  position: { x: 120, y: 80 },
  size: { width: 900, height: 640 },
})

await context.window.maximize()
await context.window.changeHeader(false)
```

Position and size accept finite pixels or relative expressions such as
`"1/2"`. `setGeometry` changes position and size as one operation. Minimized
and maximized are independent. Presentation resolves them in this order:
minimized, maximized, stored geometry. Geometry underneath is retained.
Calling `minimize()` or `maximize()` without an argument sets that state to
`true`. `raise()` brings the Window to the front of its own layer.
`changeHeader()` controls whether a standard Window presents the Desktop-owned
top region.

Window events are `move`, `resize`, `geometry`, `minimize`, `maximize`,
`changeTitle`, `changeHeader`, and `front`.

```sh
phresh window inspect --process main --program notes
```

## Layers

Windows occupy five isolated layers: `wallpaper`, `under`, `window`, `over`,
and `start-menu`. The default layer is `window`. A Program needs the `layers`
permission to use the other layers. Changing depth within one layer never
crosses into another. The taskbar remains above the window layers.

The `window` layer contains standard application windows. `under` and `over`
provide chrome-free presentation beneath and above standard windows.

`wallpaper` and `start-menu` are exclusive Desktop roles. Each can contain
one Client Endpoint. Starting another occupant in the same role ends the
existing occupant's entire Process before the replacement starts. A wallpaper
Client fills the wallpaper area. A start-menu Client fills the Start Menu
area. When either Client stops, Desktop returns that role to its fallback.

Authoritative Window values remain readable and observable for both roles.
They do not determine either role's presentation.

## Local Window

`context.localWindow` controls the representation on the current Desktop. Its
operations do not mutate authoritative Window state or emit Window events.

```ts
await context.localWindow
  .transaction({ duration: 180, easing: "ease-out", wait: true })
  .setGeometry({
    position: { x: 24, y: 24 },
    size: { width: 720, height: 480 },
  })
```

`transaction()` binds geometry, minimize, maximize, Surface, and following
operations to one visual timing. `wait: true` makes the operation resolve
after the visual transition rather than after the Desktop accepts it.
`raise()`, `changeTitle()`, and `changeHeader()` have no transaction form.

| Local operation | `window` | `under` / `over` | `wallpaper` / `start-menu` |
| --- | --- | --- | --- |
| Geometry, minimize, maximize, raise | Allowed | Allowed | Rejected |
| `changeTitle()` | Allowed | Rejected | Rejected |
| `changeHeader()` | Allowed | Rejected | Rejected |
| `addSurface()`, `removeSurface()` | Rejected | Allowed | Rejected |
| `follow()`, `unfollow()` | Allowed | Allowed | Allowed |

A standard window follows its own authoritative Window by default. Every
other layer begins unfollowed. `follow(window)` replaces the current
authoritative target and adopts only the properties permitted by the
receiving layer. `unfollow()` detaches while preserving the current local
state.

Local overrides do not break following. Later authoritative events update
only the property they carry. Under and over layers do not follow a target's
title or header. No follower copies the target's layer or Surface.
