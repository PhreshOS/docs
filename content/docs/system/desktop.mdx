A Desktop is one complete graphical representation of the System. It provides
the workspace through which a person reaches Programs, combines System
Appearance with Desktop preferences, reports the available viewport, and
belongs to the browser Connection carrying it.

Its visible environment consists of five coextensive layers ordered from back
to front: `wallpaper`, `under`, `window`, `over`, and `shell`. Every layer uses
the complete Desktop bounds. The built-in Taskbar, Start Menu, and dialog
presentation belong to `shell`, so they appear above the other layers without
reserving layout space inside them.

Appearance selects the Taskbar's edge and cross-axis size. The built-in Start
Menu is anchored to its Taskbar button and opens from that edge toward the
standard-window area, while System dialogs are centered independently within
the Shell layer.

Within the standard `window` layer, Appearance spacing defines the ordinary
surface inset and the visible gap between adjacent tiled windows. The edge
occupied by a non-overlay Taskbar instead reserves the outer spacing, the
configured Taskbar size, and one more spacing value before standard windows
begin. An overlay Taskbar leaves the ordinary inset on every edge, remains
hidden beyond its configured edge, and appears with the Appearance transaction
while the pointer occupies that edge or the Taskbar itself.

## Desktop state

Client code uses the separate `desktop` root for state belonging to the
containing Desktop:

```ts
import { desktop } from "@phreshos/client"

const { size } = await desktop.viewport.snapshot()
const preferences = await desktop.preferences.snapshot()
const connection = await desktop.connection()
```

`desktop.viewport` exposes the current workspace size in CSS pixels and emits
a complete `{ size }` snapshot when it changes.

`desktop.preferences` exposes the effective theme, animation choice, and scale
for this Desktop. Scale is a multiplier between `0.5` and `2`, defaulting to
`1`. A preference update may set `theme`, `animations`, or `scale` to
`"default"` to restore its native or System default.

```ts
await desktop.preferences.update({ theme: "dark" })
```

`desktop.connection()` returns the browser Connection carrying this Desktop.
The executing Program needs `desktopConnection` or `authentication` to access it.

## Client Windows

The System owns each running Client Endpoint's authoritative Window state. The
Desktop owns the execution document and its local representation on one
screen.

This creates two related capabilities:

- `window` is the authoritative state of the current Client execution.
- `presentation` controls or cooperates with that execution's local Desktop
  representation.

The Window and presentation always report the same layer. They do not otherwise
represent the same kind of state.

Client code reaches both Window capabilities through its Context:

```ts
import { context } from "@phreshos/client"
```

### Authoritative Window

The Window handle belongs to the Client Endpoint, but its readable and mutable
state exists only while that Endpoint is running. Reads and mutations reject
while it is stopped.

```ts
await context.window.setGeometry({
  x: 120,
  y: 80,
  width: 900,
  height: 640,
})

await context.window.maximize()
await context.window.setHeader(false)
```

Stopping the Client discards that execution's Window state. The next start
creates fresh state from the Client declaration plus the new start override;
it does not inherit mutations from an earlier execution. Existing event
subscriptions remain registered, stay silent while stopped, and observe the
new execution after it starts.

The Window exposes title, header, position, size, minimized and maximized
states, front state, and layer. Position and size
accept finite pixels or relative expressions such as `"1/2"`. A bare numeric
value is always a pixel count: `1` means one pixel, while `"1/1"` and `"100%"`
mean the complete available span.
`setGeometry()` accepts `{ x, y, width, height }` and commits position and size
atomically. Minimized and maximized are independent, and neither discards the
stored geometry. `raise()` brings a Window to the front of its own layer.

Window events are `move`, `resize`, `minimize`, `maximize`, `changeTitle`,
`changeHeader`, and `front`. An atomic
geometry change emits `move` and `resize` only for the parts that changed,
after the complete geometry has been committed.

### Presentation

`context.presentation` is a command handle for the executing Client's local
representation. It has no state snapshot or events. `layer()` is its only read
and always returns the same value as `context.window.layer()`.

In the standard `window` layer, the Desktop interprets authoritative Window
state and owns movement, resizing, snapping, minimizing, maximizing, and the
header. A custom header can hand an intentional pointer drag to that existing
Desktop behavior:

```ts
const move = context.presentation.beginMoveGesture({
  origin: { x: pressedX, y: pressedY },
  point: { x: draggedX, y: draggedY },
})

await move.ready
// The initiating document may now release its pointer capture.
await move.finished
```

`ready` resolves only after the Desktop has installed its capture surface.
`finished` resolves when the move ends or is cancelled, and `cancel()` ends an
unfinished handoff.

In `under`, `over`, and `shell`, the Desktop starts the Client document at
`{ x: 0, y: 0, width: 0, height: 0 }` and does not interpret authoritative
Window values. The Program reads its Window and chooses how to represent those
values through the raw operations `move()`, `resize()`, `setGeometry()`,
`setSurface()`, `setInteractive()`, and `raise()`.

```ts
await context.presentation
  .transactionAndWait()
  .setGeometry({
    x: 24,
    y: 24,
    width: 720,
    height: 480,
  })
```

Calling a raw operation directly applies it without a transaction.
`transaction()` resolves when the Desktop accepts a transacted operation, and
`transactionAndWait()` resolves after its visual transition finishes. Omission
uses the effective Appearance transaction, a number supplies a duration in
milliseconds with Appearance easing, and an object supplies both duration and
easing. `raise()` and `setInteractive()` are immediate and are not transacted
operations.

`setSurface(false)` removes the optional Desktop-painted backing behind the
Client document. A surface does not resize or clip the document; the Program
owns the content rendered above it.

`setInteractive(false)` removes the raw presentation from focus and pointer
hit testing, allowing pointer input to reach presentations behind it.
`setInteractive(true)` restores interaction. A new presentation starts
interactive.

Every operation exists on the shared presentation handle. An operation rejects
when its meaning is unavailable in the current layer: standard Windows reject
raw mutations, raw layers reject `beginMoveGesture()`, and wallpaper rejects
both.

### Layers

A layer gives a Client representation one ownership model.

| Layer | Representation owner | Presentation capabilities |
| --- | --- | --- |
| `window` | Desktop, interpreting authoritative Window state | `layer()`, `beginMoveGesture()` |
| `under` | Program | `layer()`, raw operations and transactions |
| `over` | Program | `layer()`, raw operations and transactions |
| `wallpaper` | Desktop, using its fixed wallpaper role | `layer()` |
| `shell` | Program | `layer()`, raw operations and transactions |

The Desktop enforces a minimum presented size of 260 by 160 logical pixels for
standard windows, limited by the available workspace, without rewriting
smaller authoritative geometry.

`wallpaper` is a fixed role whose presentation exposes only its layer. Starting
another wallpaper Client ends the existing occupant's Process before presenting
the replacement.

The `shell` layer has one Program owner at a time. Any number of Processes from
that Program may present Clients there. Before a different Program claims the
layer, the System terminates every Process currently occupying it. With no
Program-owned shell Client, the Desktop presents its built-in Taskbar, Start
Menu, and dialogs.

Layers are isolated for ordering. Raising a Window changes its depth only
within its own layer. The standard `window` layer uses the complete Desktop
bounds; Shell UI overlays it rather than reducing its geometry.
A Program needs the `layers` permission to launch outside the standard layer.

```sh
phresh window inspect --process main --program notes
```
