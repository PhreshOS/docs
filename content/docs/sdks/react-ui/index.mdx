`@phreshos/react-ui` provides the material, layout, and accessible control
primitives used by PhreshOS interfaces. It consumes Core's Appearance contract
without depending on a running System or knowing anything about Programs,
Processes, Endpoints, or Desktops.

## Quick start

Components work without a provider. They use Core's `defaultAppearance` and
follow the browser's color-scheme and reduced-motion preferences.

<ComponentPreview>
  <Preview>
    <Surface style={{ padding: 16 }}>
      Welcome to PhreshOS.
    </Surface>
  </Preview>
  <PreviewCode>

    ```tsx title="welcome.tsx"
    import { Surface } from "@phreshos/react-ui"

    export default function Welcome() {
      return <Surface style={{ padding: 16 }}>
        Welcome to PhreshOS.
      </Surface>
    }
    ```

  </PreviewCode>
</ComponentPreview>

`Surface` supplies material and edge paint. Its dimensions, padding, layout,
and semantic content remain ordinary React and CSS concerns.

## Text direction

React UI supports left-to-right and right-to-left interfaces through the same
component contracts. `AppearanceProvider` establishes the direction guaranteed
across DOM layout, keyboard behavior, overlay placement, scrolling, and
direction-sensitive animation. It follows the explicit `dir` value on the
document's HTML element unless `direction` supplies an override.

```tsx
import { AppearanceProvider, Select } from "@phreshos/react-ui"

export default function RightToLeftInterface() {
  return <AppearanceProvider direction="rtl">
    <Select
      label="Choice"
      options={[{ value: "one", label: "One" }]}
    />
  </AppearanceProvider>
}
```

Nested providers inherit the current direction unless they explicitly replace
it. `useDocumentDirection()` reacts only to changes of `<html dir>`, while
`useDirection()` returns the direction guaranteed by the nearest provider.
Direction set directly on other HTML elements remains ordinary browser behavior,
but is outside React UI's complete behavioral guarantee.

## The component model

Appearance is one source value. Components derive the scales and interaction
states they need rather than requiring a separate theme object for every
control. Surface-based components expose `color` independently from grouped
`material` customization, while layout components add no visual paint.
