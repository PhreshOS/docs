`@phreshos/react-ui` provides the material, layout, and accessible controls
used by PhreshOS interfaces. Its visual contracts accept the corresponding
System values directly. The package does not depend on a Client or Server
runtime and does not own application state.

React and React DOM are peer dependencies because the application and React
UI must share one React runtime. The current package supports React and React
DOM `19.2` within their current major versions.

```tsx
import { Button, Surface } from "@phreshos/react-ui"

<Surface>
  <Button>Continue</Button>
</Surface>
```

`Surface` supplies paint, material, edge, radius, and shadow. It does not
choose dimensions, padding, layout, overflow, or semantic content for the
consumer.

The component families divide responsibility rather than only appearance:

- `Surface` paints a material boundary; `Panel` and `Window` add specific
  structure to one.
- `Flex` and `Grid` arrange content without painting a new boundary.
- fields and selection controls own accessible input behavior and application
  values.
- `Dialog`, `Popover`, `Tooltip`, and menu triggers own distinct overlay and
  dismissal contracts.

Choose the component whose behavior matches the interface role. Styling a
generic Surface to resemble a Dialog does not provide Dialog focus,
dismissal, or accessibility behavior.

Without a provider, components use `defaultAppearance` and follow the
browser's visual preferences. `UIProvider` supplies Appearance, Preferences,
and direction for a subtree. A complete System Appearance can be passed
directly; React UI uses the visual fields it owns.

Color and material are independent. `color` accepts an Appearance color and
resting level such as `background:base` or `primary:soft`, or a direct CSS
color. `size` accepts `xsmall`, `small`, `medium`, `large`, or `xlarge`.
`disabled` prevents activation and focus; `pending` prevents activation while
retaining focus.

Controls use the shared contracts that fit their role. Most accept `size` and
`color`; Surface-based controls also accept material options. Individual
component pages state the exact capabilities they expose. A component's
hover, pressed, focused, selected, and inactive paints derive from its base
`color`; they are not separate customization values.

## Direction

React UI is direction-neutral. Native HTML inheritance handles direction when
that is sufficient. Supplying `direction="ltr"` or `direction="rtl"` to
`UIProvider` additionally establishes the guaranteed React UI direction for
JavaScript behavior and portalled content:

```tsx
<UIProvider direction="rtl">
  <Application />
</UIProvider>
```

An omitted direction creates no DOM boundary and continues through a higher
provider or the document. See [Appearance](/sdks/react-ui/appearance) for the
provider, preference, and direction resolution contracts.

React UI and the [React SDK](/sdks/react) are independent. React UI renders the
visual component language; React adapts live PhreshOS domain values to React
state. An application may use either package alone or compose them.
