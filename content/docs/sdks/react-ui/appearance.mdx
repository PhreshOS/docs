title: Appearance
description: Supply and resolve the visual source used by React UI components.
---

React UI consumes the same Core `Appearance` used by the System. The System may
own a live value, but React UI only needs one complete Appearance, one complete
set of environment preferences, and one concrete direction to render its
components.

## Resolution and inheritance

Without a provider, `useAppearance()` returns `defaultAppearance`,
`usePreferences()` follows the browser's effective theme and reduced-motion
choice, and `useDirection()` follows the document. `UIProvider` supplies these
three shared inputs to one subtree.

```tsx
<UIProvider
  appearance={appearance}
  preferences={{ theme: "dark", animations: true }}
>
  <Application />
</UIProvider>
```

Preferences are one complete `{ theme, animations }` value. A provider either
supplies that complete value or inherits it; fields are not merged separately.
Appearance follows the same whole-value rule.

`useBrowserPreferences()` exposes the browser fallback directly when an
application wants to derive or modify it before supplying a provider.
`useThemedValue(value)` selects the light or dark branch using the effective
preferences.

```tsx
function Foreground() {
  const appearance = useAppearance()
  const colors = useThemedValue(appearance.colors)

  return <span style={{ color: colors.foreground }}>Current foreground</span>
}
```

Direction remains separate from Appearance. `UIProvider` always creates a DOM
direction boundary using `display: contents`, so ordinary HTML descendants
inherit direction without gaining a layout container. Omission follows the
explicit `dir` value of the document's HTML element. Supplying
`direction="ltr"` or `direction="rtl"` establishes that direction instead.

The DOM handles direction wherever native inheritance is sufficient. React UI
reads the resolved direction in JavaScript only for behavior such as directional
keyboard interaction, logical overlay placement, scrolling, animation, and
restoring direction across a portal boundary.

`useDocumentDirection()` observes only `<html dir>` and returns a concrete
`"ltr" | "rtl"` value. A missing value, `auto`, or any unsupported value resolves
to `"ltr"`. `useDirection()` returns the nearest provider value, or the document
direction when it is used outside a provider.

```tsx
<UIProvider direction="rtl">
  <Application />
</UIProvider>
```

## One source, derived levels

Appearance provides one concrete spacing value, one radius value, and named
colors. React UI derives consistent levels around those values:

| Level | Numeric factor |
| --- | ---: |
| `xsmall` | `0.25` |
| `small` | `0.5` |
| `medium` | `1` |
| `large` | `1.5` |
| `xlarge` | `2` |

With default spacing `12`, the levels are `3`, `6`, `12`, `18`, and `24`.
With default radius `10`, they are `2.5`, `5`, `10`, `15`, and `20`.

`useScale(value)` returns this complete numeric scale for any concrete number.
`resolveSpacing()` and `resolveRadius()` instead resolve one semantic level,
number, or CSS value against an Appearance.

Colors use a parallel five-level vocabulary: `subtle`, `soft`, `base`,
`strong`, and `intense`. `base` preserves the source. The other levels derive
lighter or darker treatments from the same color.

```tsx
function BrandScale() {
  const blue = useColor("#4c9cff")
  return <span style={{ background: blue.soft }}>Soft blue</span>
}
```

`useColor()` and `useScale()` have the same role: both accept one concrete
value and return its memoized derived scale. Neither chooses an Appearance
field or theme for the caller.

## Semantic component values

A semantic color combines an Appearance color with a level, such as
`"primary:soft"` or `"default:base"`. A direct CSS color can be supplied when
the caller already owns the concrete value.

The named sources are `background`, `foreground`, `default`, `primary`,
`secondary`, `success`, `warning`, `danger`, and `info`. Theme names only select
the source palette. Components that need luminance or contrast inspect the
resolved colors.

## Material and motion

`appearance.material` supplies opacity, backdrop, grain, distortion, and
saturation independently for each theme. A component can override only the
material values it needs through its `material` prop. Color remains a separate
prop because it selects paint rather than material behavior.

`appearance.transaction` provides the duration and easing used for material,
control-state, and overlay changes. When preferences disable animations, React
UI reduces the effective duration to zero without modifying Appearance.

See [System Appearance](/system/appearance) for the complete source contract,
defaults, limits, and wallpaper values.
