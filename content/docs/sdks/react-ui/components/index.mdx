React UI components are reusable contracts built from one Appearance source.
They preserve React and native element behavior while deriving their visual
values from the nearest Appearance and Theme.

## Component domains

| Domain | Components | Responsibility |
| --- | --- | --- |
| Material | `Surface`, `Panel` | Paint material and compose material regions |
| Layout | `Flex`, `Grid` | Express parent-child layout relationships |
| Actions | `Button` | Expose accessible activation and state |
| Text fields | `Input`, `Textarea` | Edit single-line and multiline text |
| Selection | `Checkbox`, `Radio`, `RadioGroup`, `Switch`, `Select` | Choose boolean, exclusive, or listed values |
| Range | `Slider` | Select a numeric value or interval |

The component domains share Appearance, semantic color, radius, spacing, and
material conventions. They do not share a shape merely because they look
similar: each component retains the native or accessible behavior required by
its own domain.

## Composition

Use a component when it owns behavior or material. Continue to use semantic
HTML and ordinary CSS for application-specific structure.

```tsx
import { Surface } from "@phreshos/react-ui"

export default function Status() {
  return <Surface style={{ padding: 16 }}>
    <h2>Connection</h2>
    <p>Ready</p>
  </Surface>
}
```

A container remains useful when its parent-child relationship owns Grid or
Flex layout. A wrapper is unnecessary when its only child can carry the same
properties without changing semantics or behavior.
