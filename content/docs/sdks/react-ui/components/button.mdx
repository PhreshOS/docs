Use `Button` when pressing a control performs an action, such as saving a form,
opening a view, or confirming a choice. Pointer, Enter, and Space activation all
reach the same `onPress` callback.

```tsx
<Button color="primary:base" onPress={save}>
  Save changes
</Button>
```

## Pending and disabled actions

`pending` prevents a second activation while leaving the Button focusable. Use
it while an action is in progress. `disabled` removes the Button from keyboard
focus and prevents activation entirely.

```tsx
<Button color="primary:base" pending={saving} onPress={save}>
  {saving ? "Saving…" : "Save"}
</Button>

<Button disabled>Unavailable</Button>
```

## Selected props

| Prop | Use |
| --- | --- |
| `onPress` | Handle normalized pointer and keyboard activation. |
| `color` | Select an Appearance color such as `primary:base` or `danger:base`. The default is `default:base`. |
| `size` | Change the complete control scale. The default is `medium`. |
| `pending` | Block activation without removing keyboard focus. |
| `disabled` | Prevent focus and activation. |
| `material`, `shadow`, `radius` | Change the Button's Surface rendering when the normal defaults are not appropriate. |

## Guidance

Use `onPress` rather than implementing separate mouse and keyboard handlers.
The rendered element is a native button and defaults to `type="button"`, so set
`type="submit"` explicitly when it submits a form.

Text buttons provide their own accessible name. An icon-only Button must provide
one with `aria-label`.
