React UI provides several overlay compositions. Choose one according to the
interaction rather than according to appearance:

| Component | Use it for |
| --- | --- |
| `Popover` | Non-modal content anchored to a Button. |
| `DropdownMenu` | A menu opened from a Button. |
| `ContextMenu` | A menu opened by the platform context-menu gesture. |
| `Dialog` | Modal content that can allow dismissal. |
| `AlertDialog` | A modal decision that requires an explicit response. |
| `Tooltip` | A short description of a Button. |

## Popover

Use a Popover for supporting information or compact controls that remain
connected to a trigger.

```tsx
<Popover>
  <Popover.Trigger>Connection details</Popover.Trigger>
  <Popover.Content placement="bottom start">
    <Popover.Dialog aria-label="Connection details">
      <Popover.Title>Connected</Popover.Title>
      <p>Local System on port 4300.</p>
      <Popover.Close>Done</Popover.Close>
    </Popover.Dialog>
  </Popover.Content>
</Popover>
```

`Popover.Content` owns placement and Surface rendering. `Popover.Dialog` owns
the accessible content boundary inside it.

## Dropdown and context menus

Both compositions present the same `Menu`; they differ only in what opens it.

```tsx
<DropdownMenu>
  <DropdownMenu.Trigger>Actions</DropdownMenu.Trigger>
  <DropdownMenu.Content>
    <Menu aria-label="Process actions" onAction={handleAction}>
      <Menu.Item id="show">Show</Menu.Item>
      <Menu.Item id="maximize">Maximize</Menu.Item>
      <Menu.Separator />
      <Menu.Item id="close" color="danger:base">Close</Menu.Item>
    </Menu>
  </DropdownMenu.Content>
</DropdownMenu>
```

```tsx
<ContextMenu>
  <ContextMenu.Trigger>
    <ProcessItem />
  </ContextMenu.Trigger>
  <ContextMenu.Content>
    <Menu aria-label="Process actions">
      <Menu.Item>Show</Menu.Item>
      <Menu.Item>Close</Menu.Item>
    </Menu>
  </ContextMenu.Content>
</ContextMenu>
```

Compose longer menus with `Menu.Section`, `Menu.Header`, and
`Menu.Separator`. Use `Menu.Item` for the actions themselves.

## Dialog and AlertDialog

Use `Dialog` for modal work such as editing settings. Use `AlertDialog` when the
person must explicitly confirm or cancel a consequential action.

```tsx
<Dialog>
  <Dialog.Trigger>Edit profile</Dialog.Trigger>
  <Dialog.Backdrop isDismissable>
    <Dialog.Content>
      <Dialog.Header>
        <Dialog.Title>Profile</Dialog.Title>
        <Dialog.Description>Update the visible details.</Dialog.Description>
      </Dialog.Header>
      <Dialog.Body>
        <Input label="Name" />
      </Dialog.Body>
      <Dialog.Footer>
        <Dialog.Close>Cancel</Dialog.Close>
        <Button color="primary:base" onPress={save}>Save</Button>
      </Dialog.Footer>
    </Dialog.Content>
  </Dialog.Backdrop>
</Dialog>
```

`AlertDialog.Backdrop` defaults to non-dismissable and disables keyboard
dismissal. Its actions should make every available outcome explicit.

## Tooltip

Use a Tooltip for a brief description, especially when a Button's visible icon
does not explain the action on its own.

```tsx
<Tooltip>
  <Tooltip.Trigger aria-label="Information">
    <InfoIcon />
  </Tooltip.Trigger>
  <Tooltip.Content>Visible to this Program</Tooltip.Content>
</Tooltip>
```

Do not place required instructions or interactive content in a Tooltip. Use a
Popover when the content needs structure or interaction.
