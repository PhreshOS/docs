`Window` provides the visual and structural composition of a window: a fixed
header followed by a content area that fills the remaining space. It does not
create or control a PhreshOS Window handle. The consumer connects its buttons
to whichever state owner it uses.

```tsx
<Window style={{ width: 640, height: 420 }}>
  <Window.Header maximized={maximized} onMaximize={toggleMaximize}>
    <Window.Header.Identity icon="/icon.png" title="Notes" />
    <Window.Header.Center />
    <Window.Header.Actions>
      <Window.Header.Minimize onPress={minimize} />
      <Window.Header.Maximize />
      <Window.Header.Close onPress={close} />
    </Window.Header.Actions>
  </Window.Header>

  <Window.Content>
    <Editor />
  </Window.Content>
</Window>
```

## Add application actions

Use `Window.Header.Action` for an additional compact action that should match
the standard controls.

```tsx
<Window.Header.Actions>
  <Window.Header.Action aria-label="Pin" onPress={pin}>
    <PinIcon />
  </Window.Header.Action>
  <Window.Header.Minimize onPress={minimize} />
  <Window.Header.Close onPress={close} />
</Window.Header.Actions>
```

## Use the header independently

The header is available as `Window.Header` and can be placed in another
Surface without rendering the `Window` root.

```tsx
<Surface>
  <Window.Header>
    <Window.Header.Identity title="Inspector" />
    <Window.Header.Center>{/* application content */}</Window.Header.Center>
    <Window.Header.Actions>
      <Window.Header.Close onPress={close} />
    </Window.Header.Actions>
  </Window.Header>
</Surface>
```

Header parts must remain inside `Window.Header`, because the Header provides
their shared spacing, active state, control treatment, and optional maximize
action. When `maximized` and `onMaximize` are supplied to the Header,
`Window.Header.Maximize` reads them automatically, and a double-click on the
Header's drag region invokes the same action.

## Hand a drag to a window host

`Window.Header` can recognize an intentional pointer drag and hand it to an
external window host. Pass only the host's move-start function; React UI owns
the DOM pointer threshold and capture lifecycle without learning the host's
other APIs.

```tsx
<Window.Header
  beginMoveGesture={beginMoveGesture}
  onMoveError={reportError}
>
  {/* header parts */}
</Window.Header>
```

The same behavior is available through `useWindowMoveHandle()` when a custom
drag region is not a `Window.Header`. The function receives an origin and the
first intentional movement, then returns `{ ready, finished, cancel }`. React
UI retains its pointer capture until `ready` confirms that the host can receive
the pointer stream, then releases it. It cancels an unfinished handoff if the
initiating component goes away. The Header uses one drag-intent cursor before
and throughout the handoff. A host that receives the pointer in another DOM
region renders `Window.MoveCapture` for the active capture surface so that the
same interaction remains visible after ownership transfers.

## State and behavior

- `active={false}` attenuates the identity without disabling the controls.
- `Window.Header.Maximize` uses the Header's `maximized` state and
  `onMaximize` action by default. Explicit part props may replace either value.
- Header pointer handlers can connect a drag region. Center and Actions stop
  those interactions from leaking into their own controls.
- `Window.Content` grows and can shrink correctly, but it does not choose
  clipping or scrolling. Set overflow yourself or place a `ScrollArea` inside.

The Window root accepts Surface props such as `color`, `material`, `shadow`,
and `radius`. `Window.Header` accepts its own `color` for header-owned text and
icons. Every Header action is still a Button and accepts its own `color`;
`Window.Header.Close` uses `danger:base` by default.
