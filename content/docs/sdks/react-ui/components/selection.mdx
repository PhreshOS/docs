---
title: Selection
description: Represent boolean, exclusive, and listed choices with native accessible behavior.
---

Selection components share the same Appearance-aware control values and expose
normalized values instead of leaking the property names of their internal React
Aria primitives.

## Shared contracts

Visual values are uniform across the selection components:

| Property | Type | Default | Meaning |
| --- | --- | --- | --- |
| `color` | `ControlColor` | Neutral | Selected or active color |
| `size` | `ScaleLevel` | `medium` | Indicator and field size |
| `material` | `MaterialOptions` | Appearance material | Indicator or Select Surface overrides |
| `disabled` | `boolean` | `false` | Disable interaction |

Field properties remain attached to the component that owns them:

| Property | Owners | Meaning |
| --- | --- | --- |
| `label`, `description` | All selection components | Accessible visible content and description |
| `errorMessage`, `required`, `invalid` | Checkbox, Switch, RadioGroup, Select | Group or field validation |
| `readOnly` | Checkbox, Switch, RadioGroup | Preserve focus while blocking changes |

An individual Radio is an option inside RadioGroup. It does not independently
own the group's required, invalid, read-only, or error state. Select does not
expose a read-only mode; use `disabled` when its value must not be changed.

## Checkbox

Checkbox represents one independent boolean value.

| Property | Type | Default | Meaning |
| --- | --- | --- | --- |
| `checked` | `boolean` | Uncontrolled | Controlled checked state |
| `defaultChecked` | `boolean` | `false` | Initial uncontrolled state |
| `onChange` | `(checked: boolean) => void` | None | Next checked state |
| `indeterminate` | `boolean` | `false` | Mixed-state presentation |

## Switch

Switch has the same boolean value contract as Checkbox. It represents an on/off
setting and therefore does not expose an indeterminate state.

## Radio and RadioGroup

`RadioGroup` owns the selected string, validation, orientation, form name, and
arrow-key navigation. Each `Radio` contributes one required `value` and its
label.

| Property | Owner | Default | Meaning |
| --- | --- | --- | --- |
| `value` | RadioGroup | Uncontrolled | Controlled selected string |
| `defaultValue` | RadioGroup | None | Initial uncontrolled selection |
| `onChange` | RadioGroup | None | Receives the next selected string |
| `orientation` | RadioGroup | `vertical` | Layout and keyboard orientation |
| `value` | Radio | Required | Option identity |

Group `size`, `color`, `disabled`, and `material` values flow to its Radio
children. A Radio can override the values that belong to an individual option.

## Select

Select owns one string selection presented through a trigger and popup listbox.
It preserves keyboard navigation, typeahead, disabled options, focus restoration,
form submission, and form reset.

| Property | Type | Default | Meaning |
| --- | --- | --- | --- |
| `options` | `readonly SelectOption[]` | Required | Available string-valued options |
| `value` | `string \| null` | Uncontrolled | Controlled selection |
| `defaultValue` | `string \| null` | `null` | Initial uncontrolled selection |
| `onChange` | `(value: string \| null) => void` | None | Next selection |
| `placeholder` | `ReactNode` | None | Trigger content without a selection |
| `radius` | `Radius` | Appearance radius | Trigger and option radius |

```ts title="select-option.ts"
interface SelectOption {
  value: string
  label: string
  disabled?: boolean
}
```

Checkbox, Switch, and Radio render their own Surface-based indicator. Select
uses Surface for both its trigger and popup. Unselected Select options remain
transparent; keyboard focus is represented independently from selection.
