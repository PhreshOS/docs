Checkbox, Switch, Radio, and Select express different selection domains while
sharing the same visual control language. Their `color`, `size`, `material`,
disabled state, labels, and feedback follow one path through React UI.

## Boolean choices

Checkbox represents an independent boolean and can also display an
`indeterminate` mixed state. Switch uses the same `checked`, `defaultChecked`,
and boolean `onChange` contract but represents an on/off setting, so it has no
mixed state.

Both support `readOnly`, validation, description, and error feedback. Their
Surface-based indicator receives `material` customization.

## One choice from a group

`RadioGroup` owns one selected string, validation, orientation, form name, and
arrow-key navigation. Each `Radio` contributes a required `value` and its own
label. Group color, size, disabled state, and material flow to children; an
individual Radio may override values that belong to that option.

```tsx
<RadioGroup value={channel} onChange={setChannel} orientation="horizontal">
  <Radio value="stable" label="Stable" />
  <Radio value="preview" label="Preview" />
</RadioGroup>
```

Read-only and invalid state belong to the group because selection and
validation belong to the group.

## One choice from a list

Select presents one string value through a trigger and popup listbox. Each
option contains `value`, `label`, and an optional `disabled` state.

```ts
const options = [
  { value: "us", label: "United States" },
  { value: "eu", label: "Europe" },
  { value: "retired", label: "Retired", disabled: true },
] as const
```

`value` may be a string or `null`; `defaultValue` defaults to `null`.
`onChange` receives the next value. React Aria preserves keyboard navigation,
typeahead, focus restoration, form submission, and form reset.

The trigger and popup are Surfaces. Unselected options stay transparent, while
focus and selection remain distinct states. Select uses the current Appearance
transaction and animation preference for popup presence.
