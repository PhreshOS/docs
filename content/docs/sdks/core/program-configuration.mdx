---
title: Program configuration
description: Describe a Program project, its Endpoints, and its installation behavior.
---

`phresh.config.ts` describes how a Program project becomes a runtime Program.
`defineConfig()` gives that file contextual typing and returns the supplied
value unchanged. It does not create, build, or install anything by itself.

```ts title="phresh.config.ts"
import { defineConfig } from "@phreshos/core"

export default defineConfig({
  identity: "notes",
  name: "Notes",
  version: "1.0.0",
  permissions: {
    network: ["https://api.example.com"],
  },
  server: {
    location: "dist/server",
    worker: "main.js",
  },
  client: {
    location: "dist/client",
    title: "Notes",
  },
})
```

Node Project reads this file and derives a development or production
[Program](/runtime/programs) definition. See [Node Project](/sdks/node/project).

## Identity and resources

`identity` is the required stable kebab-case name used by the System. `name`,
`version`, and `description` describe the Program to people. `icon`, `agent`,
`categories`, `keywords`, and `website` describe its public resources and
catalog presence. When `version` is omitted, the resolved Program version is
`0.0.0`.

An icon is a Program-relative PNG between 128 and 2,048 pixels per side and
no larger than 5 MiB. `agent` names a Program-relative Markdown document
explaining the Program's own identity and tool contract to agents.

`buildCommand` runs before a production start, installation, or package is
created.

`permissions` declares the System capabilities the Program requests. Runtime
permission state may override each declared assignment. See
[Permissions](/system/security/permissions).

## Endpoint declarations

A Program must declare a Server, a Client, or both. Each declaration names
its production location and the defaults used when a Launch does not make
another choice. `start` defaults to `true`; `service` defaults to `false`.
At least one declared Endpoint must start in the default Process.

A Server chooses exactly one execution mechanism:

```ts
server: {
  location: "dist/server",
  worker: "main.js",
  devCommand: "vite-node server/main.ts",
}
```

`command` starts a supervised operating-system process, `worker` loads an
ECMAScript module in a Node.js Worker, and `sandbox` loads a bundled
ECMAScript module in a capability-contained JavaScript runtime. A production
Server chooses exactly one. Development remains separate and uses
`devCommand` when declared. Optional `installCommand` and
`uninstallCommand` prepare and clean the production Server location.

A Client location contains its production `index.html`. `sandbox` defaults to
`true`, which runs that document in an iframe sandbox allowing scripts and
forms. Setting it to `false` removes the iframe's `sandbox` attribute entirely.

The Client declaration can also choose the initial Window title, header state,
size, position, layer, minimized state, and maximized state:

```ts
client: {
  location: "dist/client",
  sandbox: true,
  layer: "over",
  size: { width: 800, height: 600 },
}
```

The values initialize each Client execution's authoritative Window. See
[Desktop](/system/desktop) for layer ownership and local presentation control.

When neither a Launch nor the Client declaration supplies a value, the System
uses these initial defaults:

| Window value | Default |
| --- | --- |
| `title` | Program name |
| `layer` | `window` |
| `position` | `{ x: 120, y: 80 }`, offset for concurrently open Windows |
| `size` | `{ width: 520, height: 340 }` |
| `minimize`, `maximize` | `false` |
| `header` | `true` in `window`; `false` in other layers |

The Desktop owns the standard Window surface. Raw layers start their local
presentation at zero geometry and without a surface until the Program issues
presentation commands.

`devUrl` selects an existing HTTP or HTTPS server. When a Client
`devCommand` is supplied without `devUrl`, Node Project selects an
available port and provides `PHRESHOS_CLIENT_PORT` and `PHRESHOS_CLIENT_BASE`.

Server and Client `location` values are resolved from the project directory.
`worker` and `sandbox` are module paths contained within the Server location.
Production Server `command`, `installCommand`, and `uninstallCommand` execute
from that Server location. `buildCommand`, `server.devCommand`, and
`client.devCommand` execute from the project directory so they can use the
project's development tooling.

The authoring Config does not contain the runtime `storage` field: Node Project
derives that absolute directory when it creates the concrete
`ProgramDefinition`.

## Installation launch

`installLaunch` asks the System to create one Process after installation
succeeds. It is an installation default, not stored runtime state and not the
meaning of opening a Program in a particular interface.

```ts
export default defineConfig({
  identity: "notes",
  installLaunch: { name: "main", client: true },
  client: { location: "dist/client" },
})
```

`true` uses an empty Launch and therefore the Endpoint declaration defaults.
Omission means installation does not launch a Process unless the installation
operation supplies its own `launch` option. That option can also override the
definition with a specific Launch or disable it with `false`. See
[Programs](/runtime/programs).
