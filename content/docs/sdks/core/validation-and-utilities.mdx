title: Validation and utilities
description: Read untyped input into canonical Core values at real boundaries.
---

Core parsers exist for places where TypeScript cannot establish the value:
files, JavaScript callers, transport messages, and user input. A parser
either returns the canonical contract value or rejects because the operation
cannot continue with that value.

Already typed application values do not need to be repeatedly parsed.

```ts
import { isPermissionName, parsePermission } from "@phreshos/core"

function readPermission(name: unknown, value: unknown) {
  if (!isPermissionName(name)) throw new Error("Unknown permission")
  return parsePermission(name, value)
}
```

## Domain boundary helpers

The public guards recognize Service addresses, upload keys, Window layers,
relative geometry values, and permission names. Parsers canonicalize Launch
values, Program definitions, installation options, Appearance, permissions,
network and Storage scopes, shell events, and shared domain snapshots.

Scope helpers also answer containment questions:
`networkScopeCovers(grant, requested)` compares network regions, while
`describeStorageScope(scope)` exposes a Storage scope's operation set, path,
and recursive flag.

```ts
import { networkScopeCovers, parseNetworkScope } from "@phreshos/core"

const grant = parseNetworkScope("https://*.example.com/v1/**")
console.log(networkScopeCovers(grant, "https://api.example.com/v1/items"))
```

Runtime parsing validates only values needed by the boundary. Additional
object properties remain inert rather than invalidating an otherwise usable
value.

## Immutable contract data

Core exports stable values that consumers need to interpret contracts:

- `programPermissionCatalog` maps each permission to its value domain
- `layers` contains the valid Window layers
- `appearanceLimits` contains the supported numeric Appearance bounds
- `defaultAppearance` is the complete default visual document
- `desktopPreferencesLimits` and `defaultDesktopScale` bound Desktop scale
