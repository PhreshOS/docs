title: Domain contracts
description: Shared entities and capabilities implemented by PhreshOS SDKs.
---

When two environments need the same entity or capability, they use the same
Core contract. The meaning of those contracts is documented under
[Runtime](/runtime) and [System](/system). This page names what Core exports.

## Domain objects

The four runtime components are `Program`, `Process`, `Endpoint`, and
`Service`. `ServerEndpoint` and `ClientEndpoint` specialize the shared
Endpoint role. `Connection` and `Session` model browser authentication.
These are classes because their identities matter at runtime as well as in
TypeScript.

```ts
import { Process, Program } from "@phreshos/core"

const program = await system.program.find("notes")
const process = program && await program.firstProcess()

console.log(program instanceof Program)
console.log(process instanceof Process)
```

Within one SDK context, repeated navigation to the same live identity returns
the same handle.

## Capability contracts

Some contracts describe a capability rather than a new entity. `System` is
the root of global capabilities. `Context` is the execution-local view of an
Endpoint. `Desktop`, `Window`, `LocalWindow`, `Storage`, `Network`,
Appearance, and permissions describe the behavior their implementing
environment must provide.

These interfaces can have local and remote implementations. What stays fixed
is the observable result: accepted input, returned values, events, authority,
and lifecycle.

## Reusable communication behavior

`Publishable`, `Subscribable`, `Askable`, and `Timeoutable` express behavior
shared by several domains. See [Communication](/runtime/communication).

```ts
const cleanup = endpoint.subscribe("changed", value => {
  console.log(value)
})

cleanup()
```

Core preserves the event map through higher-order adapters, so an SDK or
React hook can infer the event name and message from the supplied handle.
