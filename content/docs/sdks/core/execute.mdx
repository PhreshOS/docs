---
title: Execute
description: One discoverable JSON interface over ordinary System handles.
---

Execute represents selected SDK operations as JSON requests and JSON results.
It gives agents, command-line tools, and other generic consumers one stable
interface.

Every request names a domain and operation through reserved fields. The other
fields belong to that operation:

```ts
const result = await system.execute({
  $domain: "endpoint",
  $operation: "ask",
  program: "notes",
  process: "main",
  endpoint: "server",
  event: "document.list",
  input: null,
})
```

The adapter resolves and invokes the same public handles available to
ordinary SDK code. Visibility, permissions, not-found behavior, and operation
errors retain their existing meaning. A failed operation rejects the Promise.

`phresh execute` is the same interface from the terminal:

```sh
phresh execute '{"$domain":"operation","$operation":"list"}'
```

## Static and untyped requests

`ExecuteRequest` is inferred from the authoritative operation schemas, so a
request authored in TypeScript is checked before it runs. Values received
from an external tool begin as `unknown` and are read through the same
schema:

```ts
import { parseExecuteRequest } from "@phreshos/core"

const request = parseExecuteRequest(externalValue)
const result = await system.execute(request)
```

Environment SDKs implement `system.execute()`. Execute contracts and parsers
remain imported from Core.

The catalog itself is local contract data. Generic tooling can inspect it
without a System connection:

```ts
import {
  describeExecuteOperation,
  listExecuteOperations,
} from "@phreshos/core"

const endpointOperations = listExecuteOperations("endpoint")
const ask = describeExecuteOperation("endpoint", "ask")
```

`listExecuteOperations()` returns summaries and accepts an optional domain
filter. `describeExecuteOperation()` returns the operation description and its
JSON request and result schemas, or `null` for an unknown pair. The equivalent
`operation.list` and `operation.describe` requests exist so a remote JSON-only
consumer can discover the same catalog through `execute()`.

## Discovery

The `operation` domain describes the interface itself:

```ts
await system.execute({
  $domain: "operation",
  $operation: "list",
  domain: "endpoint",
})
```

Description returns the meaning and JSON request and result schemas of one
operation:

```ts
await system.execute({
  $domain: "operation",
  $operation: "describe",
  domain: "endpoint",
  operation: "ask",
})
```

These descriptions come from the same schemas used to validate execution.

## Catalog

Execute covers Program, Process, Endpoint, Service, and Window operations, plus
discovery.

| Domain | Operations |
| --- | --- |
| `operation` | `list`, `describe` |
| `program` | `list`, `find`, `agent`, `definition`, `getStartup`, `enableStartup`, `disableStartup`, `pinned`, `pin`, `unpin`, `getPermission`, `listPermissions`, `allowsPermission`, `allowPermission`, `denyPermission`, `requestPermission`, `logs`, `wait` |
| `process` | `list`, `find`, `create`, `findOrCreate`, `exit`, `wait` |
| `endpoint` | `inspect`, `start`, `stop`, `waitReady`, `ask`, `publish`, `wait`, `waitLifecycle` |
| `service` | `list`, `search`, `inspect`, `waitReady`, `ask`, `publish`, `wait`, `waitLifecycle`, `waitDiscovery` |
| `window` | `inspect`, `move`, `resize`, `setGeometry`, `minimize`, `maximize`, `setTitle`, `setHeader`, `raise`, `wait` |

Program logs use the Program handle's existing read-only SQL capability.
The `logs` table has columns `createdAt`, `process`, `source`, `kind`, and
`content`.
