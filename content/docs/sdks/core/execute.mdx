---
title: Execute
description: Use one discoverable JSON interface over ordinary System handles.
---

Execute represents selected SDK operations as JSON requests and JSON results.
It gives agents, command-line tools, and other generic consumers one stable
interface without creating another execution mechanism inside the System.

Every request names a domain and operation through reserved fields. The other
fields belong to that operation:

```ts
const result = await system.execute({
  $domain: "endpoint",
  $operation: "ask",
  program: "tilo",
  process: "tilo-server",
  endpoint: "server",
  event: "board.list",
  input: null
})
```

The adapter resolves and invokes the same public handles available to ordinary
SDK code. Visibility, permissions, not-found behavior, and operation errors
therefore retain their existing meaning. A failed operation rejects the
Promise; errors are not converted into successful JSON results.

## Static and untyped requests

`ExecuteRequest` is inferred from the authoritative operation schemas, so a
request authored in TypeScript is checked before it runs. Values received from
an external tool begin as `unknown` and are read through the same schema:

```ts
import { parseExecuteRequest } from "@phreshos/core"

const request = parseExecuteRequest(externalValue)
const result = await system.execute(request)
```

Environment SDKs implement `system.execute()`. Execute contracts and parsers
remain imported from Core rather than being re-exported by each SDK.

## Discovery

The `operation` domain describes the interface itself. Listing can be narrowed
to one domain:

```ts
await system.execute({
  $domain: "operation",
  $operation: "list",
  domain: "endpoint"
})
```

Description returns the meaning and JSON request and result schemas of one
operation:

```ts
await system.execute({
  $domain: "operation",
  $operation: "describe",
  domain: "endpoint",
  operation: "ask"
})
```

These descriptions come from the same schemas used to validate execution, so
discovery and behavior share one operation catalog.

Program logs are exposed as the Program handle's existing read-only SQL
capability:

```ts
await system.execute({
  $domain: "program",
  $operation: "logs",
  identity: "terminal",
  statement: "select createdAt, process, source, kind, content from logs order by createdAt desc limit ?",
  values: [100]
})
```

## Boundary

Execute is local to the SDK. The JSON request is not sent to a generic Execute
route in the authoritative System. The adapter turns it into ordinary handle
operations, and those operations cross their established boundaries normally.
