---
title: Permissions
description: Inspect, request, and assign Program authority.
---

Permissions belong to the Program. The Client Context exposes the same
permission handle as every Program, already bound to the executing Program. The catalog and
visibility rules are documented under [Permissions](/system/security/permissions).

```ts
import { context } from "@phreshos/client"

const allowed = await context.permissions.allows("uploads")

if (!allowed) {
  await context.permissions.request("uploads")
}
```

`get` returns the effective assignment after stored state is resolved over the
Program declaration. `all` returns the effective snapshot. `allows` reports whether that permission permits the requested
capability. `request` prompts the owner, replaces the stored permission, and
returns the resulting canonical value. Approval returns the granted list,
denial returns `false`, and dismissal or expiry returns `null`.
`timeout(milliseconds)` selects another deadline for the prompt; the default
is two minutes.

`request()` always creates an owner decision. It does not skip the prompt when
the Program already has the same or broader authority. A request initiated by
an Endpoint remains tied to that execution's lifetime.

`context.permissions` and `program.permissions` both expose `get`, `all`,
`allows`, `allow`, `deny`, `request`, and `timeout`. `allow()` replaces the
complete stored assignment with an allowed value; `deny()` stores `false`.
Those two direct mutation operations require `all`. The other operations
require access to the target Program, so an accessible Program handle can also
request an owner decision on that Program's behalf.
