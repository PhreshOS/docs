---
title: System access
description: Use the complete System contract through Client authority.
---

`system` has the same public contract in Client, Server, and Node. The Client
implementation does not remove members from its TypeScript shape; authority
determines whether a particular operation may execute.

```ts
import { context, system } from "@phreshos/client"
```

## Capabilities

| Member | Capability |
| --- | --- |
| `program` | List, find, create, and observe Programs |
| `process` | List, find, and observe Processes |
| `connection` | List, find, and observe browser Connections |
| `session` | List, find, and observe authentication Sessions |
| `service(key)` | Address one Server or Client Service |
| `storage` | Access the native filesystem |
| `uploads` | Read or create System uploads |
| `appearance` | Read or replace System Appearance |
| `network.fetch()` | Perform an outbound standard request |
| `network.websocket()` | Open a standard WebSocket |
| `shell()` | Stream an operating-system command |

Every capability's complete operation contract lives under [System](/system).
This page defines only what changes at the Client boundary.

## Default authority

Without additional permissions, a Client can access its own Program and the
Processes, Services, and resources belonging to that Program. It may read
Appearance, Desktop state, and existing uploads.

Access to another Program also covers its Services. A narrower `services`
permission can grant only those Services without exposing the Program.
`desktopConnection` exposes this Desktop's Connection and its Session;
`connections` exposes the complete Connection and Session registries and also
grants that narrower capability. Native Storage, outbound System networking,
upload creation, Appearance updates, Desktop preference updates, restricted
layer selections, shell execution, and unrestricted Program permission
management require their corresponding permissions.

```ts
if (await context.permissions.allows("network", ["https://api.example.com"])) {
  const response = await system.network.fetch("https://api.example.com/status")
  console.log(await response.json())
}
```

## Standard platform results

`system.network.fetch()` accepts standard `RequestInfo | URL` and `RequestInit`, then
returns a standard `Response`. `system.network.websocket()` returns the platform's
standard `WebSocket` after its asynchronous authority boundary.

```ts
const socket = await system.network.websocket("wss://events.example.com")

socket.addEventListener("message", event => {
  console.log(event.data)
})
```

The asynchronous factory is the only difference from `new WebSocket()`.
Once returned, the socket uses the standard interface.

## Failure behavior

Registry lists contain only visible handles, searches return `null` for hidden
identities, and events and relationships omit hidden entities. Using an
inaccessible or fabricated handle reports that the handle does not exist.

An explicit non-lookup capability rejected by Client authority fails with
`Execution is not permitted`. A synchronous operation that cannot represent
failure remains silent.

A permission change governs later System operations. It does not retroactively
revoke a `Response` or `WebSocket` already returned to the Client.
