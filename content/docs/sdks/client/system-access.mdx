---
title: System access
description: Use shared System capabilities from a Client Endpoint.
---

Client `system` is the same [System](/system) contract as Server and Node.
Visible Programs, Processes, Services, Connections, and Sessions are those
the executing Program is allowed to see. Operations the Program is not
allowed to perform reject. Lookups for inaccessible identities return
`null`.

```ts
import { system } from "@phreshos/client"

const programs = await system.program.list()
const appearance = await system.appearance.snapshot()
```

Without additional permission, the Client sees its own Program and Processes
and can read Appearance, its Desktop viewport and preferences, and known upload
keys. Permission values extend visibility to selected foreign Programs,
Services, Connections, and Sessions. Collections filter hidden handles, and
lookups return `null` rather than revealing whether an inaccessible identity
exists.

`system.execute()` is available here with the same JSON catalog.
`system.shell()` requires `all`. Native storage requires a covering
`storage` scope.

Direct capabilities reject when unauthorized. This includes network requests,
upload creation, Appearance updates, Desktop preference changes, restricted
Window layers, shell execution, and permission administration. A permission
change governs later operations; it does not revoke a `Response`, WebSocket, or
other platform value that was already returned.

See [Runtime](/runtime) for Program and Process operations, and
[Permissions](/system/permissions) for how visibility is decided.
