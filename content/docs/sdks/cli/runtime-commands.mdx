---
title: Runtime commands
description: Navigate and operate the Program, Process, Endpoint, and Window domains.
---

Runtime commands follow the same ownership model as the SDKs. Each command
connects to the running System, resolves the requested handles, performs one
operation, and closes its Node connection.

## Programs

`program list` searches and pages visible Programs. `program inspect` reads one
Program's declaration and installation state. `program agent` prints the
Program's own agent document. `program wait` observes either the System Program
registry or one Program's Process, uninstall, and forget lifecycle.

```sh
phresh program list --installed-only
phresh program inspect --program terminal --json
phresh program wait --event uninstall --program terminal
```

## Processes

Process commands list, inspect, create, find-or-create, exit, and observe live
Processes. A Program identity gives a local Process name its namespace.

```sh
phresh process create \
  --program terminal \
  --name main \
  --server \
  --client
```

Endpoint flags translate directly into Core's Launch contract.
`--server-service` and `--client-service` select Service roles;
`--no-server` and `--no-client` omit an Endpoint. Repeatable
`--option name=value` entries become immutable Process options.

With `--name main --replace`, creation ends the existing Program-local named
Process before starting its replacement.

## Endpoints

Endpoint commands inspect, start, and stop Server or Client incarnations. They
can wait for either kind's lifecycle, publish or await an event, and ask a
Server Endpoint a question. `wait-ready` is available for Server Endpoints,
whose readiness is distinct from existence.

```sh
phresh endpoint ask \
  --program terminal \
  --process main \
  --endpoint server \
  --event status.read \
  --json
```

The Process and Endpoint kind form the address. `--program` is required when
the Process coordinate is a local name. CLI payloads use JSON even though SDK
communication supports richer binary boundary values.

## Windows

Window commands read and change authoritative Window state: move, resize,
atomic geometry, minimize, maximize, title, header visibility, layer-local
raising, and future events.

```sh
phresh window set-geometry \
  --program terminal \
  --process main \
  --x 0 \
  --y 0 \
  --width 100% \
  --height 100%

phresh window change-header --program terminal --process main --hide
```

Geometry accepts the same pixel and workspace-relative values as Core.
`--restore` supplies `false` to minimize or maximize. Camel-case commands also
provide the kebab-case aliases shown by `phresh describe`.
