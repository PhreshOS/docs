---
title: System access
description: Use the permission-constrained System contract from a Server Endpoint.
---

Server `system` implements the complete Core System contract across the Server
execution boundary. Every operation is evaluated with the same Program-owned
permissions used by the Client SDK.

```ts
import { system } from "@phreshos/server"

const programs = await system.program.list()
const connections = await system.connection.list()
```

The root provides Program, Process, Connection, and Session collections;
Service addresses; Storage and uploads; Appearance; Network; and shell
execution. Each operation has the same name, input, result, and lifecycle as in
the Client and Node implementations. See [System](/system) for those contracts.

## One boundary in every environment

System operations do not execute directly through the Server runtime's local
facilities. Network, shell, Storage, uploads, domain handles, and Context
operations all cross the same boundary to the System. The System owns their
implementation and applies the Program's permissions there.

```ts
const response = await system.network.fetch("https://api.example.com/status")

for await (const event of system.shell("node --version")) {
  if (event.event === "output") console.log(event.text)
}
```

When the Endpoint stops, its attached requests, sockets, streams, and command
trees are released.

This guarantee applies to the System API, not to capabilities independently
provided by the execution environment. A command or Worker can still use its
Node.js host access directly. A Sandbox provides only its JavaScript runtime
and the System boundary, making Program permissions the effective outside
capability boundary for that Server.

`system.service(key)` returns `ServerService` or `ClientService` according to
the `endpoint` coordinate. Only the Server Service supports questions.
