---
title: System access
description: Use the complete System contract from a Server Endpoint.
---

Server `system` is the same [System](/system) contract as Client and Node.
The executing Program's permissions decide which other Programs, Services,
Connections, and Sessions are visible, and which System operations may run.

```ts
import { system } from "@phreshos/server"

const programs = await system.program.list()
await system.appearance.update({ spacing: 14 })
```

`system.shell()` requires `all`. Native storage requires a covering
`storage` scope. Network, uploads, Appearance, and the rest of `system`
follow the same Program permission state.

Reading or following `system.logs` requires `logs`. A visible Program handle
includes access to its own `program.logs`. Their shared query and event
contract is documented under [Logs](/system/logs).

Every Server SDK operation crosses the Endpoint boundary to the authoritative
System. `system.execute()` is an adapter over those same handles, so it does
not introduce another authority path. Streams, sockets, requests, and shell
command trees attached through that boundary are released when the Server
execution context ends.

The Server execution mode is a separate question. A `command` or `worker`
process has its own operating-system access. A `sandbox` does not. See
[Execution](/sdks/server/execution).
