---
title: Permissions
description: Inspect, request, and assign Program authority.
---

Permissions belong to the Program and apply equally to its Server and Client
Endpoints. Server `context.permissions` is bound to the current Server
Endpoint and its Program.

```ts
import { context } from "@phreshos/server"

const allowed = await context.permissions.allows("uploads")

if (!allowed) {
  await context.permissions.request("uploads")
}
```

`get()`, `all()`, and `allows()` inspect effective authority. `request()` asks
the owner for a decision unless the effective assignment already equals the
requested value; that exact match resolves immediately. `timeout(milliseconds)`
selects a request deadline. The request ends with `null` if this Server
Endpoint stops.

Program handles expose a separate management contract through
`program.permissions`: `get()`, `all()`, and `allows()` read assignments;
`allow()` and `deny()` replace them and require `all`. Program handles cannot
create requests because they do not identify a requesting Endpoint.

Callers with `all` can list and observe pending requests through
`system.permissions`, then use each `PermissionRequest` handle to allow, deny,
or cancel it.

The permission value model, visibility rules, mutation semantics, and request
lifecycle are documented under [Permissions](/system/security/permissions).
